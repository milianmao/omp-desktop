# 测试策略

两层测试，互不重叠：**JS 回归脚本**（`tests/*.mjs`，覆盖 `src/app/` 的纯逻辑）与 **Rust 单元/集成测试**（`#[cfg(test)] mod tests` + 分套件 `*tests*.rs`）。没有 Python、没有 JS 测试框架、没有 e2e 浏览器驱动层——DOM 由脚本内的桩对象代替，Chromium 由真实进程代替。

## 一、JS：无依赖的 node 脚本

### 1.1 一个模块一个脚本

```
tests/test-<name>.mjs   ←→   src/app/<name>.js
```

- 文件头 `#!/usr/bin/env node`，紧跟一段注释说明**脚本覆盖什么、为什么存在**（多数文件叙述曾经的 bug），末行 `// Run: node tests/test-<name>.mjs`。
- 只依赖 Node 内建模块：`node:assert/strict`、`node:fs`、`node:path`、`node:url`、`node:vm`，必要时 `node:test` 与 `node:child_process`。**没有任何 npm 依赖**（`package.json` 的 `devDependencies` 只有 `@tauri-apps/cli`），所以 CI 里不需要 `npm ci`（`.github/workflows/tests.yml` 的 js job 只跑 `actions/setup-node` + `npm test`）。
- 命名例外（`AGENTS.md` § Commands 明列）：`test-markdown.mjs` 覆盖 `app/marked-setup.js`；`test-recent-models.mjs` 覆盖 `adapter.js`；`test-tool-output.mjs` 覆盖 bash 工具卡；`test-updater-json.mjs` 覆盖 `.github/scripts/updater-json.mjs`；`test-widget-examples.mjs` 覆盖 `examples/widgets/git.sh`（经 `app/widgets.js` 解析）；`test-browser-runtime.mjs` 覆盖 `app/browser-screen.js` 与 `app/use-browser.jsx`。
- `test-rpc.mjs` 是**唯一的探针**，不覆盖模块，需要活的 `omp`，**不在** `npm test` 链里（仅 `node tests/test-rpc.mjs` 手动跑）。

### 1.2 加载被测 IIFE 模块的三种写法

模块都是 `(function(){ …; window.X = X; })()` 形式，测试因此不能 `import`，只能自己造一个 `window`：

**(a) `new Function("window", src)(win)`** — 最常用（36 个脚本）。适合纯同步、无宿主 API 的模块：

```js
// tests/test-widgets.mjs
const win = {};
new Function("window", readFileSync(join(root, "src/app/widgets.js"), "utf8"))(win);
const W = win.OMP_WIDGETS;
```

依赖顺序必须手写：`tests/test-terminal.mjs` 先喂 `app/keymap.js`，再 `app/project-nav.js`、`app/path-setting.js`，最后才是 `app/terminal.js`，因为后者在顶层读 `window.OMP_KEYMAP`。

**(b) `vm.createContext` + `vm.runInContext`** — 需要多个模块共享一个 realm 时（`test-transcript-merge.mjs`、`test-markdown.mjs`、`test-recent-models.mjs`、`test-tool-output.mjs`、`test-conversation-tree.mjs`、`test-remote-client.mjs`）：

```js
// tests/test-transcript-merge.mjs
const ctx = vm.createContext({ console });
ctx.window = ctx;                       // window 即 globalThis
for (const file of ["app/turn-status.js", "app/transcript-merge.js", "adapter.js"]) {
  vm.runInContext(readFileSync(join(root, "src", file), "utf8"), ctx, { filename: file });
}
const { mergeTranscript } = ctx.OMP_TRANSCRIPT;
```

`ctx.window = ctx` 让模块内的 `window.X = X` 落到同一对象上；`adapter.js` 直接把函数挂到全局，所以 `ctx.adaptAgentMessages` 可直接取用。

**(c) `vm.runInNewContext`** — 多个独立 `window`，或需要在同一进程里重跑 `live.js`（`test-browser-runtime.mjs`、`test-remote-view.mjs`、`test-goal.mjs`）：

```js
runInNewContext(source("src/app/constants.js"), { window });
runInNewContext(source("src/app/browser.js"), { window, URL });
```

### 1.3 断言约定

- 自己的 `check(label, fn)` 帮助函数包 `assert`，失败时打印 `FAILED: <label>` 再 `throw`；末尾 `console.log(\`test-<name>: ${passed} checks passed\`)`。40 个脚本用这个样式。
- `test-browser-runtime.mjs` / `test-remote-view.mjs` 改用 `node:test` 的 `test(name, fn)`（支持 `await`），因此没有 `checks passed` 收尾；这两个是唯一有异步断言的脚本。
- 跨 realm 的比较：游标对象原型不同，`deepEqual` 会拒，先 `JSON.parse(JSON.stringify(v))` 再比（`test-browser-runtime.mjs` 的 `own()`，`test-remote-view.mjs` 同名函数）。
- 用真实数据形状建夹具，不造假：`test-transcript-merge.mjs` 的消息体注明取自 omp 18.6.0 会话。

### 1.4 DOM / React 桩

`tests/test-browser-runtime.mjs` 是唯一需要 DOM 与 React 的脚本，全部自带：

- `node(extra)`：EventTarget 替身，`addEventListener`/`removeEventListener` 记在 `Map`，`fire(type, ev)` 同步跑监听器。
- 帧缓冲用真 `ArrayBuffer` + `DataView`（`wire(cssW, cssH, seq)` 构造 17 字节头）。
- `rAF` 用 `Map<id, callback>` 手动 flush；`setTimeout` 收进数组。
- `fakeReact()`：按调用位置分槽的 `useState`/`useRef`/`useMemo`/`useCallback`/`useEffect`，外加 `render`/`unmount` 模拟 commit，因此**不依赖 hook 调用顺序之外的任何东西**。
- 只 `runInNewContext(source("src/app/use-browser.jsx") + "\nuseBrowser", …)` 取函数——该 hook 内部无 JSX 字面量（返回对象由调用方渲染），所以无需 Babel。

### 1.5 接入 `npm test`

- 新脚本**必须**同时加进 `package.json` 两处：`scripts.test` 的 `&&` 链，以及自己的 `test:<name>` 脚本。当前链 = 44 个 `node tests/test-*.mjs` + 末尾一条 `node scripts/build-frontend.mjs`（构建 `dist/` 兼做 CSP 校验，是 `npm test` 的最后一步）。
- 单跑：`node tests/test-<name>.mjs` 或 `npm run test:<name>`。
- 链是顺序执行，任一脚本非零退出即整链失败——`check()` 用 `throw` 而非 `process.exit`，就是为了让 Node 带栈退出。

## 二、Rust：行内 module + 分套件文件

### 2.1 行内 `#[cfg(test)] mod tests`

所有纯/逻辑函数在同文件底部带 `#[cfg(test)] mod tests`（AGENTS.md § Tests 强制要求）。当前 `src-tauri/src/` 下 **110 个 `.rs` 文件含 `#[cfg(test)]`**，共 **1113 个 `#[test]` 函数**（无一 `#[tokio::test]`——crate 自己不 spawn 任务，Tauri 持有 runtime）。

集成行为（spawn、IPC、reader）要求「一条 happy path + 一条主要失败路径」。

### 2.2 `src-tauri/src/test_support.rs`：共享轮询助手

`#[cfg(test)]` 模块，多个套件共用，**复制它里面的东西是被明确禁止的**（AGENTS.md § Repo map）：

| 助手 | 语义 |
|---|---|
| `eventually<T>(timeout, check)` | 每 10 ms 轮询 `check` 直到 `Some`，超时返回 `None`；返回找到的值本身 |
| `wait_until(timeout, cond)` | `eventually` 的 bool 版 |
| `shell(script)` | 平台 shell 命令：Windows `cmd /C`，unix `sh -c` |
| `executable(path, content)` | 写一个可执行替身（unix 置 0755），返回路径 |
| `tempdir(scope, name)` | 全新空目录 `omp-<scope>-<name>-<pid>`；`scope` 用来隔开共用同一进程的套件 |
| `TempDir` | 带 `Drop` 的 `tempdir`，测试失败也会清理 |
| `tls_client_config(cert_pem)` | 只信任指定证书的 rustls 客户端，供 remote 套件用 |

`terminal/test_support.rs` 是终端**私有**的补充层（`open_with` 注册标签页并开 shell、`stdout_of` 取子进程 stdout），不入公共文件。

**没有 `sleep` 后直接断言的写法**：所有等待都走 `eventually`/`wait_until`；`terminal/tests_windows.rs` 顶部注释写明「Every wait polls with a generous timeout: no timing is asserted」，`SLOW = 30s`。

### 2.3 分套件文件

大模块把测试拆到独立文件，用 `#[cfg(test)] mod tests;`（同名 `tests.rs`）或 `#[cfg(..)] #[path = "xxx_tests.rs"] mod xxx_tests;` 挂载：

| 套件 | 文件 / 挂载点 |
|---|---|
| browser | `browser/tests.rs`（生命周期 + 全部 browser 套件共用的支持代码：真 Chromium 跳过、manager/panel 工厂、假 CDP client）；子套件 `browser/view/tests.rs`、`browser/proxy/tests.rs`、`browser/annotate/tests.rs`、`browser/broker/tests.rs`（broker 的 test fake） |
| terminal | `terminal/mod.rs` 里 `#[cfg(all(test, unix))] mod tests;` + `#[cfg(all(test, windows))] mod tests_windows;`——**按平台二选一**，`tests.rs` 开真 `sh` PTY，`tests_windows.rs` 开 `cmd.exe` 的 ConPTY |
| remote | `remote/{bridge,commands,devices,http,lock,manager,push,push_subs,server,settings,tls,tracker}_tests.rs`，各由对应模块 `#[path = …]` 挂载；`ws_tests.rs` 例外，由 `server_tests.rs:91` 挂 `#[path = "ws_tests.rs"] mod ws_tests;`；另有 `remote/net/windows_tests.rs` |
| conversation_tree / saved_sessions / keybindings | `tests.rs`（各 731 / 488 / 431 行） |

子套件通过 `use super::super::tests::{…, CHROMIUM};` 反向复用父模块的夹具（如 `browser/annotate/tests.rs:18`）。

### 2.4 真实 Chromium 测试与开关

- `browser/tests.rs::chromium_or_skip(test)`：按应用同样的发现逻辑（`SettingsStore::load(None, home_dir()).launch_candidates()`）找浏览器。
  - 找不到且未设 `OMP_REQUIRE_CHROMIUM=1` → `eprintln!("skip {test}: no chromium …")` 返回 `None`，测试**带注释地通过**。
  - 设了 `OMP_REQUIRE_CHROMIUM=1`（CI）→ `panic!`，浏览器缺失即失败。
  - 找到则先 `warm_up`：`static WARM: Once`，全进程只跑一次 `chromium --headless=new --no-first-run --dump-dom about:blank`，上限 60 s，理由是冷启动（磁盘缓存冷、杀毒扫描）可能超过应用 10 s 启动超时，否则测试会误报启动失败。
- `CHROMIUM: Mutex<()>`（`browser/tests.rs:14`）：**跨模块共享一把锁**，从夹具创建前持有到 teardown。加锁走 `browser/mod.rs:46` 的 `lock()` = `mutex.lock().unwrap_or_else(PoisonError::into_inner)`——**容忍中毒**，一个真浏览器测试 panic 不会连带拖垮其后的所有套件。

### 2.5 Cargo 侧的验证命令

三条命令（`cargo fmt` → `cargo test --locked` → pedantic+nursery clippy）的完整写法与理由见 [编码规范 § 2.1](编码规范.md)，此处不重复。

Rust 侧特有的两点补充：

- `clippy.toml` 的 `disallowed-methods`（`Command::spawn/output/status`、`SlavePty::spawn_command`、`open::that*`、`gix::discover/open`）**只在本地这条 clippy 命令里检查，CI 不跑 clippy**；`lib.rs` 用 `#![cfg_attr(test, allow(clippy::disallowed_methods))]` 把测试豁免掉。
- `cargo check --locked` 已无独立价值：`cargo test` 会编译 crate 与测试（`tests.yml` 头注释的原话），所以 CI 不再单跑 check。

## 三、什么算覆盖

AGENTS.md § Tests「What counts」，逐字执行：

| 算 | 不算 |
|---|---|
| 导入函数并对**输出**断言 | 只验证「不抛异常」 |
| 覆盖 happy path + 主要失败路径（集成行为） | 快照测试 |
| 从真实数据形状构造的夹具 | 「it renders」式渲染检查 |
| 用 `eventually` 断言最终状态 | `sleep` 之后断言时序 |

- 新增逻辑不带测试的 commit 会被拒。
- `live.js` 的新事件处理 / 新 bridge 方法：要么给 notebook 式正确性证明，要么在提交说明里解释为何副作用太强无法直接测。
- 一条硬性交叉检查在 Rust 侧：`agent/mod.rs::every_command_live_js_sends_is_allowed`（`mod.rs:605`）用 `include_str!("../../../src/live.js")` 扫字面量 `{ type: "…"`，与 `ALLOWED_COMMAND_TYPES` 比对——**JS 改协议、Rust 测试兜底**。
- JS 侧没有 lint 流水线（无 ESLint 配置），`// eslint-disable-next-line no-new-func` 注释只是习惯。

## 四、分层执行矩阵

| 改了什么 | 提交前必须跑 |
|---|---|
| 只改 `src/app/*.js` 纯逻辑 | `node tests/test-<name>.mjs` → `npm test` |
| 改 `src/live.js` / `src/adapter.js` / 新增 RPC 命令 | `npm test` + `cd src-tauri && cargo test`（真值表由 `every_command_live_js_sends_is_allowed` 守） |
| 只改 `src-tauri/src/` Rust | `cargo fmt` → `cargo test` → clippy（pedantic+nursery） |
| 改 `src/index.html` / `src/design/` / 新增文件 | `npm test`（末步 `node scripts/build-frontend.mjs` 会校验 CSP 与 `?v=` 规则） |
| 两个子项目都动 | 全套：`npm test` + `cargo fmt` + `cargo test` + clippy |
| 准备发版 | 以上全部；Windows/macOS/Linux 的矩阵与 `OMP_REQUIRE_CHROMIUM=1` 由 CI 兜 |

CI 侧：`.github/workflows/tests.yml` 是 `workflow_call` 可复用工作流（rust job 三平台 `cargo test --locked` + `OMP_REQUIRE_CHROMIUM: "1"`；js job `node 24` + `npm test`）。`ci.yml` 在 PR 与命中 `src-tauri/**`、`src/**`、`tests/**`、`package.json`、`scripts/**`、`.github/scripts/**` 的 master push 上调用它；`release.yml` 先调它，不通过则什么都不构建。CI 与 release 共用同一套，无法漂移。
→ 详见 [Git工作流与CI](../05-项目开发规范/Git工作流与CI.md)
