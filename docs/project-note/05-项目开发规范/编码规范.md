# 编码规范

本文只收录 **AGENTS.md § Code style / § God-file prevention / § IIFE rule** 与真实代码中可验证的约定。每条规则都标注了出处；无出处的一律不写。

## 1. 通用原则

|规则|出处|
|---|---|
|先沿用既有架构模式，再考虑引入新模式|AGENTS.md § Code style / General|
|先可读性，再分配效率|同上|
|提交前本地跑 fmt + lint，不让 fmt / clippy 失败|同上|
|只格式化**本次实际修改**的文件，禁止纯格式化的批量重写|同上|
|优先外科式 `edit`，而非整文件 `write`|同上|

整文件重写只在三种情况下允许（AGENTS.md 原文）：(a) 新建文件；(b) 真的改掉 >~70% 行；(c) 重构需要的锚点太多、`edit` 已不可靠。仅为改几行而重写会丢格式、丢未注意到的不变量、放大 diff。

## 2. Rust

### 2.1 工具链与 edition

- edition **2021**，stable 工具链；只有 clippy 用 nightly（`src-tauri/Cargo.toml:5`）。
- 没有 `rust-version` 键。用较新特性前先查 `Cargo.toml`，不要假设 2024 edition 的写法（`gen` blocks、RPIT lifetime capture 变更）可用。
- 完成前验证顺序（AGENTS.md § Code style / Rust）：

```
cargo fmt
cargo test --locked
cargo +nightly clippy --all-targets --all-features -- -W clippy::pedantic -W clippy::nursery -D warnings
```

pedantic + nursery 比泛用的 `clippy -D warnings` 严格得多；`redundant_clone`、`too_many_arguments` 在此处是硬错误。

### 2.2 错误处理：IPC 边界是 `Result<T, String>`

- `thiserror` / `anyhow` **不是**依赖，且是刻意如此。Tauri 把命令错误序列化给 JS，所以边界就是 `Result<T, String>`（示例：`src-tauri/src/approval_mode.rs:191`）。
- 不在边界上的命令返回 `ProfileList`、`Option<String>`、`Vec<String>` 或什么都不返回。
- 内部 helper 跟随同一形状：`json_store::with_lock_str`（`src-tauri/src/json_store.rs:584`）存在的唯一目的就是把 `String` 错误穿进 `io::Error`。
- 只有当新增的是真正“库形状”的模块、且调用方要对错误变体做匹配时，才可引入 `thiserror`；不要为改造既有 `String` 错误而引入。

### 2.3 `unwrap` / `expect`

除 `#[cfg(test)]` 外禁止使用，除非该不变量确实不可恢复**且**有注释（参见 `run()` 上带文档的 `# Panics` 段）。

### 2.4 借用与所有权

- 参数优先借用：`&str`、`&[T]`、`&Path`；只在需要所有权时才取 owned。
- 不做无意义的 `String` ↔ `&str` 互转。
- 迭代器优先于下标循环；不要为了遍历一次而 `collect` 进 `Vec`；长度已知时用 `Vec::with_capacity`；`Cow` 只在可测量地减少分配时使用。
- 泛型能解决的地方不用 `Box<dyn Trait>`；不引入多余的 `Arc` / `Mutex` / async 原语；生命周期保持简单。
- 热路径（reader 循环、逐行分发、IPC payload 构造）尽量减少临时分配。
- 模块级 `#![allow(clippy::needless_pass_by_value)]`（在 `lib.rs`）是有意的：Tauri `#[command]` 要求 owned 类型。

### 2.5 Clone 阶梯（每个存活的 `.clone()` 都必须承重）

写 clone 之前，按此顺序执行（AGENTS.md 原文顺序）：

|级|动作|说明|
|---|---|---|
|1|**改用借用**|取 `&T`、返回 `&T`，或缩小作用域让原值仍然存活|
|2|**改用移动**|最后一次读之后只用一次的值不需要拷贝——这是最常见的多余 clone。`FnOnce` 闭包、`match` 分支、函数尾部都能拿走所有权（`file.startup = next;` 而不是 `next.clone()`）|
|3|**重构结构**|把消耗性使用算到最后，让前面那次可以借用；或改用 index/id 代替副本|
|4|**此时才 clone，并在调用点写原因**|注释说明的是*为什么这份复制是有意的*，不是“这是一次 clone”|

Clone 专项规则：

- 引用计数自增一律 `Arc::clone(&x)` / `Rc::clone(&x)`，**绝不**裸写 `x.clone()`（示例：`src-tauri/src/agent/mod.rs:211`、`agent/approvals.rs:199`）。裸 `.clone()` 在调用点与深拷贝无法区分；`clone_on_ref_ptr` 属 `restriction`，不在 pedantic/nursery 里，因此**靠约定与评审执行**。
- 绝不 `.clone()` 进一个已存在的绑定（`*dst = src.clone()`）——那是 `clone_from`，`assigning_clones` 在这里是硬错误。
- 绝不用 clone 去平复借用检查器。borrowck 报错是生命周期/结构问题，clone 只是把它藏起来，并给每次调用加一次分配。
- 绝不 clone `Copy` 类型、本可直接透传的 `&str`、或只用于迭代的集合。
- **测试不豁免**，“被调方需要 owned 值”不构成理由——它是该重构的信号。跨调用点重复的 clone 属于某个 helper，或该类型需要一个消耗型访问器。先例在 `profiles.rs`：15 处 `let path = store.path.clone(); drop(store);` 变成 `store.into_path()`，5 处 `ProfileStore::load(store.path.clone())` 变成 `store.reopen()`，该文件 clone 净减 21 → 6，六个都带原因。
- 通过 lint 闸门的 clone 要么已论证，要么落在盲区。评审把没有注释的 clone 当作 finding。

### 2.6 异步

- Tauri 拥有 tokio runtime；本 crate 不自建任务。
- **绝不**跨 `.await` 持有 `std::sync::Mutex` guard。现存锁（`AgentBridge.sessions`、`ProfileStore.cache`、`RuleBook`）都在同步块内获取并释放，保持这一点。
- 长耗时/阻塞工作走 `spawn_blocking`（见 `list_saved_sessions`、`git_browser_status`；封装处 `src-tauri/src/lib.rs:155-160`）。
- 无阻塞操作放进 async 命令；`kill+wait` 放到线程外（见 `start_session` / `stop_session`）。

### 2.7 `unsafe`

规则：没有 `// SAFETY:` 注释就不写 `unsafe`。生产代码中 `unsafe` 只存在于**七个**模块：

|模块|用途|
|---|---|
|`src-tauri/src/supervisor.rs`|Win32 job objects（`CreateJobObjectW` / `SetInformationJobObject` / `AssignProcessToJobObject` / `CloseHandle`，终端的 shell 经 `attach_process` 同样走这里）；unix 的 `libc::kill`；`pid_is_alive`（unix `kill(pid,0)`，Windows `OpenProcess`/`GetExitCodeProcess`/`GetLastError`）；`kill_group_if_leader`（`getpgid`/`getpgrp` + 进程组 `SIGKILL`，绝不杀应用自身进程组）|
|`src-tauri/src/terminal/kill.rs`|`libc::kill`/`getsid` 按 session id 杀终端；`libc::waitid` 观察 shell 退出而不回收；macOS 的 `proc_listallpids`|
|`src-tauri/src/program_setting.rs`|`is_executable_file` 中 unix 的 `libc::access(X_OK)`：std 没有安全等价物|
|`src-tauri/src/browser/process/pipe.rs`|Chromium 的 CDP 管道：unix 用 `pre_exec` + `fcntl`/`dup2`/`close` 落到 fd 3/4，Windows 用 `SetHandleInformation`（在独占 spawn gate 内）|
|`src-tauri/src/browser/proxy/peer.rs`|对端 OS 用户校验：Windows `GetExtendedTcpTable` / `OpenProcessToken` / `GetTokenInformation` / `EqualSid` 等，句柄交给 `OwnedHandle::from_raw_handle`；macOS `geteuid`|
|`src-tauri/src/remote/net.rs`|unix `libc::getifaddrs`/`freeifaddrs`，枚举活跃的非 loopback IPv4 接口|
|`src-tauri/src/remote/lock.rs`|锁屏探测：macOS 对 `CGSessionCopyCurrentDictionary` 字典做 `cast_unchecked`；Windows `WTSQuerySessionInformationW(WTSSessionInfoEx)` + `WTSFreeMemory`；Linux 用 zbus，无需 unsafe|

新测试代码调用这些 helper（`kill::process_exists`、`supervisor::pid_is_alive`），不自己写 FFI。有安全 std API 时优先用它：unix 进程组用 `Command::process_group(0)`，管道本身来自 `std::io::pipe`。

### 2.8 进程与 lint 强制项

- 每个子进程都经 `spawn_gate.rs`（`spawn`/`output`/`status`，或为“替我们发起”的 spawn 取 `spawn_gate::shared()`）。
- `src-tauri/clippy.toml` 的 `disallowed-methods` 拒绝 `Command::spawn`/`output`/`status`、`SlavePty::spawn_command`、`open::that*`、`gix::discover`/`open`。**只在本地 clippy 命令里检查，CI 不跑 clippy**。

## 3. 前端

### 3.1 开发期没有打包器

`tauri dev` 直接从 `src/` 提供页面，JSX 由 `@babel/standalone` 在浏览器内转译；release 才用预编译的 `dist/`（`npm run build:frontend`，`scripts/build-frontend.mjs`）。因此：没有模块解析器、没有 import 图、没有 tree-shaking——加载顺序由 `src/index.html` 手写。

### 3.2 IIFE 规则（必守）

普通 `<script>` 共享 document 顶层作用域，Babel `type="text/babel"` 脚本又通过解构与之相交。因此：

> 每个声明了顶层 `const`/`function`/`class` 的普通脚本，**必须**写成 `(function(){ …; window.X = X; })();`。

- 参考实现：`src/app/constants.js`（文件头注释直接解释了原因）、`src/app/settings-tab.js`、`src/design/tweaks/use-tweaks.js`、`src/app/turn-status.js`。
- 裸的 `window.X = {…}` 赋值可以不用包裹（`model-names.js`）。
- Babel 转译的文件（`.jsx`、`app-live.jsx`）不需要包裹。

### 3.3 Babel 共享顶层作用域

所有 Babel 脚本共享同一个顶层作用域：解构要用**唯一别名**（如 `_TD_Fmt`），绝不出现同名 `const` 的第二次声明。否则抛 SyntaxError，整份 bundle 失效。

### 3.4 脚本顺序 = 依赖图

- 顺序：vendored 库 → `app/marked-setup.js` → 普通 `app/*.js` IIFE 模块 → `tweaks/use-tweaks.js` → `design/ui/` primitives → `design/chat/` → `design/subagents/` → `design/*` → `model-names.js` → `app/turn-status.js` → `app/session-prefs.js` → `app/transcript-merge.js` → `adapter.js` → `app/session-title.js` → `live.js` → `app/use-*.jsx` → `app-live.jsx` 最后。
- 顶层解构全局（`const { X } = window`）的文件必须排在定义它的文件之后；错序会静默得到 `undefined`。函数体内的查找是晚绑定的，与顺序无关。
- `live.js` 在其 IIFE 顶层初始化时读取的普通 `app/*.js` 模块，必须排在 `live.js` 之前。
- 新增文件要插到**正确位置**，绝不追加；拆分后按依赖顺序更新。逐文件的完整理由见 `docs/architecture/frontend-load-order.md`。

### 3.5 JSX 不得依赖 DOMContentLoaded

`dist/` 的 deferred 脚本在 DOMContentLoaded/load **之前**执行，Babel 的在其后执行。因此 JSX 不能依赖这两个事件，也不能读 `document.readyState`。窗口控件用 document 级 click delegation，而不是 `_setupWindowChrome` 里的一次性 `querySelector`。

### 3.6 无内联处理器、无 CDN

- `index.html` 中不得出现内联 `<script>` 或 `on*=` 属性（release CSP `script-src 'self'`；`build-frontend.mjs` 会让构建失败）。Babel/React 标签保持朴素写法，构建脚本按字面匹配它们。
- 资源引用里绝不手加 query、fragment、空白、`&`、`\` 或 CDN URL；`@import` 只接受 app 相对的裸路径——`?v=<version>` 由 `build-frontend.mjs` 追加，且遇到其他形式 fail-closed。
- React/ReactDOM/Babel/marked/hljs/xterm/jsQR 全部 vendored，应用必须离线可用。jsQR 的库体永不手改；xterm 由 `scripts/vendor-xterm.mjs` 生成。

### 3.7 前端格式

AGENTS.md 要求 Prettier 风格、尊重任何已存在的 ESLint 配置、保持既有 import 顺序。当前仓库**没有** JS lint/format 配置（`package.json` 无 prettier/eslint 依赖，也无配置文件），也没有 JS lint 流水线；`npm test` 只跑回归脚本。

## 4. God-file 软上限与拆分

|类型|上限|
|---|---|
|`.jsx`|~250 行|
|`.js`|~400 行|
|`.rs`|~250 行|
|`.css`|~300 行|

是指引而非硬限，内聚性比行数重要。

1. 按职责拆，不按符号数量拆；同类组件成族（如 `chat/`），绝不按字母拆。
2. 带自己非平凡 state/effects 的组件一文件一个（如 `EvalCell`、`ScrubbableDiff`、`AnnotablePlan`）。
3. 仅当一个是另一个的私有 helper 时才共置（`InlinePlan` 与 `AssistantBubble`）。
4. CSS 按视觉层拆，不按组件；`chat.css` 除非某层超过 ~150 行，否则不二次拆。
5. Rust 模块在有多个 `pub` 面或一长段私有 helper 时按关注点拆。
6. 拆分后按依赖顺序更新 `src/index.html`，绝不追加。
7. 不为对称而抽取；紧耦合的层（如 `chrome.jsx`）保持在一起。

触发条件：单个文件出现第 6 个主要组件，或单个 Rust 模块出现第 4 个不相关关注点 → 在继续变大之前拆。

## 5. 命名与文件放置

|我要加的东西|放在哪|约定|
|---|---|---|
|纯逻辑模块（可测、无副作用）|`src/app/<name>.js`|IIFE 包裹，暴露 `window.OMP_<NAME>`（`Object.freeze({...})` 形式见 `src/app/turn-status.js` 尾部）|
|该模块的回归测试|`tests/test-<name>.mjs`|`node tests/test-<name>.mjs` 直接跑；同时要在 `package.json` 的 `npm test` 链里加一项，并加自己的 `test:<name>` 脚本|
|React hook（把 bridge 状态接到 UI）|`src/app/use-<name>.jsx`|文件名 `use-` 前缀；不是纯逻辑，不进 `app/*.js` 测试链|
|UI 组件|`src/design/` 下按家族分目录|`chat/`、`ui/`（primitives）、`settings/`、`git/`、`subagents/`、`widgets/`、`browser-*`、`layout/`|
|新 Rust 特性模块|`src-tauri/src/<feature>/` 或单文件 `<feature>.rs`|按 `AGENTS.md` § Repo map 里的既有分组；一特性一个目录（如 `browser/`、`terminal/`、`remote/`）|
|Tauri 命令注册|`src-tauri/src/lib.rs` 的 `generate_handler!`|同时把新命令加进文档与（若前端要发）`ALLOWED_COMMAND_TYPES`|
|特性说明文档|`docs/architecture/<feature>.md`|**改该特性的代码前必须先读对应文件**；新特性也要补一份，并加进 AGENTS.md 的表格|

`src/design/` 是线上接线副本；根目录 `design/` 是被 gitignore 的只读原型参考。**绝不**从 `design/` 重新生成 `src/design/`（会覆盖 bridge 接线），直接改 `src/design/`。

## 6. Tauri / IPC 边界

- 保持 FE/BE 边界显式，不暴露不必要的命令。
- 所有跨 IPC 的输入都要校验/消毒，payload 强类型。
- 策略留在 Rust：终端、浏览器、widget 的前端只发 tab id、尺寸、输入、ack、游标，**绝不**发 cwd、程序路径、命令、触发器或上下文。
- 平台相关逻辑隔离（如 `CREATE_NO_WINDOW` 只在 `agent/spawn.rs`）。

→ 详见 [服务层与IPC通信](../04-数据与组件设施/服务层与IPC通信.md)

## 7. 评审实际会查的 Do / Don't

|Do|Don't|
|---|---|
|`Result<T, String>` 作为命令返回值|引入 `thiserror`/`anyhow` 重写既有错误|
|`&str` / `&Path` / `&[T]` 参数|参数取 `String`/`Vec` 再到处借用|
|移动（`file.startup = next;`）|`next.clone()` 拷贝一次性的值|
|`Arc::clone(&x)`|`x.clone()` 碰引用计数|
|`dst.clone_from(&src)`|`*dst = src.clone()`|
|clone 调用点写“为什么这份复制是有意的”|靠 clone 平复借用检查器|
|`.await` 之外的同步块里拿锁|跨 `.await` 持 `std::sync::Mutex` guard|
|阻塞工作进 `spawn_blocking`|在 async 命令里做阻塞 I/O|
|新增 `unsafe` 带 `// SAFETY:`|在七个模块之外新增 `unsafe` FFI|
|`spawn_gate::spawn` 起子进程|直接 `Command::spawn` / `open::that` / `gix::open`|
|普通脚本包 IIFE + `window.X = X`|顶层裸 `const`/`function` 泄漏到 document 作用域|
|按唯一别名解构（`_TD_Fmt`）|Babel 顶层同名 `const` 二次声明|
|把新脚本插到依赖位置|把新脚本追加到 `index.html` 末尾|
|无 handler 标记 + 容器级 delegation|内联 `on*=` / 内联 `<script>`|
|本地 vendored 资源|CDN 链接、`convertFileSrc()`|
|只格式化改过的文件|顺手格式化无关文件 / 全库重排|
|`edit` 定点修改|为改几行整文件 `write`|
|提交前 `cargo fmt` → `test` → `clippy`|提交 fmt/clippy 失败的分支|
