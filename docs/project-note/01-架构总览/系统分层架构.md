# 系统分层架构

OMP Desktop 是 `omp`（oh-my-pi，一个 CLI 编码 agent）的桌面外壳。它不重新实现 agent，而是**每个标签页拉起一个 `omp --mode rpc-ui` 子进程**，用 JSON 行协议（stdout 出、stdin 入）驱动它，并把 omp 的 RPC 事件渲染成聊天界面。

## 三层加两条侧链

```
┌──────────────────────────────────────────────────────────────────────┐
│ ① Rust 后端  src-tauri/src/  （Tauri 2, edition 2021）                 │
│    AgentBridge        HashMap<session_id, BridgeInner>                │
│    BrowserManager / TerminalManager / WidgetHost / RemoteManager      │
│    JSON 存储：profiles / open-tabs / recent-projects / terminal / …    │
└───────────────▲───────────────────────────┬──────────────────────────┘
                │ Tauri commands (IPC)      │ Tauri events
                │ Result<T, String>         │ agent://line/{id} 等
┌───────────────┴───────────────────────────▼──────────────────────────┐
│ ② 桥接层  src/live.js + src/adapter.js                                 │
│    window.OMP_BRIDGE（命令） / window.OMP_DATA（渲染数据）              │
│    每个标签页的 live state + sessionRegistry（标签页注册表）            │
└───────────────▲───────────────────────────┬──────────────────────────┘
                │ useBridgeSnapshot         │ notify()
┌───────────────┴───────────────────────────▼──────────────────────────┐
│ ③ React   src/app-live.jsx（唯一根）+ src/app/*.js 纯逻辑              │
│           + src/app/use-*.jsx 钩子 + src/design/** 组件                │
└──────────────────────────────────────────────────────────────────────┘

侧链 A：src/remote/  手机端页面（纯 JS，由 Rust 内嵌资源提供，走 TLS + WebSocket）
侧链 B：src-tauri/src/browser/  per-tab headless Chromium + CDP broker + agent 代理端点
```

### 依赖方向（单向，理论上不可逆）

`design/**` → `app/use-*.jsx` → `live.js` → Rust。反向依赖只有两种合法形式：Rust 发 Tauri 事件、Rust 通过命令返回值/事件回传。

**实测偏差（503 文件全量扫描，重跑方式见文末）**：共 15 处越界，均为历史遗留，改到相关文件时应顺手收敛：

| 层 | 文件 | 越界内容 |
|---|---|---|
| design-ui | `composer.jsx` | 直接读 `OMP_DATA`、调 `OMP_BRIDGE.listFiles/recentModels/refreshModels`、读 `window.__TAURI__` |
| design-ui | `history-modal.jsx`、`usage-stats-panel.jsx`、`chat/file-preview.jsx`、`widgets/widget-blocks.jsx`、`approval-mode-section.jsx`、`approval-rules-panel.jsx` | 直接调 `OMP_BRIDGE.*` |
| design-ui | `design/data.js` | 未在 `index.html` 加载的死文件，重新定义 `window.OMP_DATA`（可删） |
| react-hooks | `use-remote.jsx` | 读 `OMP_TWEAKS_STORE`（`live.js` 也这么读，见下） |
| react-hooks | `use-pane-widths.jsx` | 直接调 `useEdgeDrag` |
| app-logic | `image-attach.js`、`marked-setup.js` | 触碰 DOM（`document.createElement`）——纯逻辑层的纯度例外 |
| js-bridge | `live.js` | 读 `OMP_TWEAKS_STORE`（启动时早于 React 的必要读取） |

`app-logic` 是共享工具层而非栈上某一级，因此允许被 hooks 与 design 同时引用。

## 各层职责边界

| 层 | 唯一职责 | 明确**不**做的事 |
|---|---|---|
| Rust | 进程生命周期、文件与 git 读取、权限校验、路径选择、协议编解码、限流 | 不做 UI 决策、不保存 UI 视图状态 |
| `live.js` | RPC 帧的解析与分发、每标签页状态机、命令封装 | 不做布局/动画、不含样式 |
| `app/*.js` | 纯函数：状态归约、数据整形、判定规则 | 不碰 DOM、不调 IPC（唯一例外：`live.js` 本身） |
| `use-*.jsx` | 把桥快照与事件接成 React 状态、副作用生命周期 | 不做纯逻辑（下沉到 `app/*.js` 以便测试） |
| `design/**` | 渲染与交互外观 | 不持有业务状态、不调 IPC |

### 为什么 `live.js` 有 4576 行

它是**一个标签页的全部运行时状态机**：RPC 帧分发（`_dispatchEnvelope` → `_handleEvent`/`_handleResponse`）、每标签页状态快照与恢复、命令封装、队列/审批/重命名/goal 的子协议。AGENTS.md 承认这是历史结构，"`_handleResponse` 的 if 链一旦括号错位整个 IIFE 就语法错误"，属于已知风险而非设计目标；新行为优先落到 `app/*.js` 纯模块再接入。→ 详见 [已知问题与陷阱](../06-迭代与变更/已知问题与陷阱.md)

## 前端加载顺序即依赖图

`tauri dev` 不打包：`src/index.html` 里每个 `<script>` 按顺序执行，`type="text/babel"` 的文件由浏览器内 Babel 现场编译。顺序错误不会报错，只会让 `const { X } = window` 拿到 `undefined`。

四个必须记住的约束：

1. 普通 `<script>` 模块用 IIFE 包裹并挂 `window.X`，避免顶层 `const` 冲突。
2. Babel 脚本共享同一顶层作用域：解构必须用唯一别名（`_TD_Fmt`）。
3. 延迟执行的 `dist/` 脚本在 `DOMContentLoaded` **之前**运行：JSX 不得依赖 `readyState` 或该事件。
4. 文件插入位置按依赖顺序，**永远不追加到末尾**。

→ 详见 [组件架构与通信](../04-数据与组件设施/组件架构与通信.md)、`docs/architecture/frontend-load-order.md`

## 两个进程间协议的形状

| 通道 | 方向 | 载体 | 说明 |
|---|---|---|---|
| Tauri command | 前端 → Rust | `invoke("name", camelCaseArgs)` | 参数一律 camelCase，错误是 `String` |
| Tauri event | Rust → 前端 | `agent://line/{id}`、`agent://exit/{id}`、`terminal://data/{id}`、`git://branch/{id}`、`widgets://run`、`remote://*`、`update://progress`、`open://project`、`window://close-requested` | 事件名按会话 id 拼接，只有活动标签页监听 |
| omp RPC | Rust ↔ omp | stdin/stdout 各一行 JSON | 前端经 `send_command` 下发，`ALLOWED_COMMAND_TYPES` 白名单校验 |

→ 详见 [服务层与IPC通信](../04-数据与组件设施/服务层与IPC通信.md)

## 安全边界（三条）

1. **webview 是不可信执行环境的假设**：Rust 只接受已注册标签页的 id，路径一律由 Rust 决定（shell 路径、Chromium 路径、项目文件夹），webview 从不发送 spawn 用的可执行文件路径。
2. **Chromium 不开放端口**：`--remote-debugging-pipe` 是唯一 CDP 入口，broker 独占；面向 agent 的占位端口做同用户内核态校验。
3. **git 过滤驱动不可被仓库劫持**：`git_browser::open` 在内存中剥掉仓库自身 config 定义的 filter driver。

→ 详见 [设计模式与策略](../02-功能结构和策略/设计模式与策略.md)、`docs/architecture/browser.md`
