# 部署与运行架构

## 两种前端形态

| 形态 | 前端来源 | CSP | Babel | 用途 |
|---|---|---|---|---|
| dev | `src/`（`build.frontendDist: "../src"`） | `script-src 'self' 'unsafe-inline'` | 浏览器内编译每个 `text/babel`（≈1.5 s/次） | `npm run dev` |
| release | `dist/`（`tauri.dist.conf.json` 覆盖） | `script-src 'self'` | 无（已预编译为 `<script defer>`） | `npm run build` |

两份配置的 CSP 只差 `'unsafe-inline'` 一个 token，`build-frontend.mjs` 会校验这个差异并在越界时构建失败。编辑时必须两个文件一起改。

## 命令表

| 任务 | 命令 |
|---|---|
| 安装 Tauri CLI | `npm install` |
| 开发 | `npm run dev` |
| 发布构建 | `npm run build`（= `tauri build --config src-tauri/tauri.dist.conf.json`） |
| 只构建 `dist/` | `npm run build:frontend`（也被 `npm test` 作为最后一步执行） |
| Rust 检查 | `cd src-tauri && cargo check --locked` |
| Rust 格式化 | `cd src-tauri && cargo fmt` |
| Rust lint（必须干净） | `cd src-tauri && cargo +nightly clippy --all-targets --all-features -- -W clippy::pedantic -W clippy::nursery -D warnings` |
| Rust 测试 | `cd src-tauri && cargo test` |
| 全部 JS 回归 | `npm test` |
| 单个 JS 回归 | `node tests/test-<name>.mjs` |
| 探测 omp RPC（需真实 omp） | `node tests/test-rpc.mjs` |

## `dist/` 构建管线（`scripts/build-frontend.mjs`）

1. 用**同一个 vendored Babel** 和 script-tag loader 完全相同的选项编译每个 `.jsx`，保证 `dist/` 跑的是浏览器本来会跑的字节码。
2. 把 `<script type="text/babel">` 改写成 `<script defer src="….js">`：defer 脚本在解析阻塞脚本之后、按文档顺序执行；执行时机在 `DOMContentLoaded` **之前**（Babel 的在之后）。
3. 丢弃 Babel 与 development React，React 标签改指 production 构建。
4. 给 `index.html` 里每个脚本 `src`、样式 `href`，以及 `dist/**/*.css` 里每个相对 `@import`，追加 `?v=<tauri.conf.json version>`。
5. 任何找不到的标签、或产物引用了不存在的脚本 → 构建失败（fail closed）。

**为什么必须打版本戳**：Windows 的 WebView2 数据目录（`%LOCALAPPDATA%\dev.ohMyPi.desktop\EBWebView`）在应用内更新后**仍然保留**，而 Tauri 的内嵌资源响应不带 ETag/Last-Modified/Cache-Control。同名 URL 可能命中上一版的 HTTP 缓存，导致加载图混用新旧文件（0.4.0 之后真实发生过：文件夹选择器能打开但没有标签页出现）。版本号每版必变，戳记必然 miss。

**CSS 引用禁令**：不要在 `src/index.html` / `src/**/*.css` 手工给资源加 query、fragment、空白、`&`、`\` 或 CDN URL；`@import` 只允许裸的、应用相对引号或 `url()` 路径。

## 配置分层

| 文件 | 内容 | 何时合并 |
|---|---|---|
| `src-tauri/tauri.conf.json` | 主配置：窗口、CSP、updater 端点与公钥、bundle 目标与打包模板 | 始终 |
| `src-tauri/tauri.dist.conf.json` | `beforeBuildCommand` + `frontendDist` + 严格 CSP | `npm run build` / release |
| `src-tauri/tauri.release.conf.json` | `bundle.createUpdaterArtifacts` | **只有** `release.yml` |

`createUpdaterArtifacts` 刻意不放在主配置里：放进去会让每次本地 `npm run build` 因缺签名私钥而失败。

## 主窗口与平台细节

```json
{
  "label": "main", "width": 1440, "height": 900, "minWidth": 480, "minHeight": 320,
  "decorations": false, "shadow": true, "dragDropEnabled": false
}
```

| 配置 | 为什么 |
|---|---|
| `decorations: false` | 无边框窗口，靠 DWM + `platform.css` 画边距/阴影 |
| `dragDropEnabled: false` | Tauri 原生文件拖放会吞掉页面所有拖放事件（Windows 连 HTML5 拖拽都吞），关掉才能让 composer 接收粘贴图片（#50） |
| `minWidth/minHeight 480×320` | AeroSpace 等平铺窗口管理器可以塞进窄列（0.12.0 从 960×640 下调） |
| `withGlobalTauri: true` | 页面用 `window.__TAURI__` 直接调命令 |
| `assetProtocol.enable: false` | 不开放 asset 协议；文件预览走 `project_file_read` 返回 base64 |

## 打包产物

| 平台 | 目标 | 特殊打包文件 |
|---|---|---|
| Windows | `.msi` + NSIS `.exe` | `packaging/windows-folder-verb.{nsh,wxs}`（"Open with OMP Desktop" 文件夹动词） |
| macOS | `.dmg` + `.app.tar.gz`（arm64 / x64 分开构建） | `packaging/Info.plist`（`CFBundleDocumentTypes` + 本地网络用途说明） |
| Linux | `.AppImage` + `.deb` + `.rpm` | `packaging/omp-desktop.desktop`（`MimeType=inode/directory`、`Exec` 必带 `%F`） |

Windows 的 `.wxs` 里 `Win64` 是重新推导的（预处理器宏不跨文件传递）：写成 32 位会写进 `Wow6432Node`，64 位资源管理器永远看不到。

## 更新流程（应用内）

```
app_update_check  →  插件更新源 latest.json（最新已发布的正式版）
                  →  minisign 公钥校验
                  →  把 Update 停在 UpdaterState，返回 UpdateInfo（下载 URL 不过 IPC）
app_update_install → （可选）update://progress 事件节流上报
                   →  仅 AppImage / MSI / NSIS / .app 自装；其余通知型，打开 release 页
```

**重启会跳过 `Drop`**：卸载路径统一走 `lib.rs::kill_child_processes`，顺序是远程服务 → omp 子进程 → Chromium → widget 插件 → 终端 shell 树。不要覆盖 updater 插件的 `on_before_exit`（它在启动安装器**之前**运行，此刻杀 omp 一旦安装失败会让所有标签页瘫痪）。

## 环境要求

| 项 | 要求 |
|---|---|
| `omp` | 在 PATH 上（Windows 常见位置 `%LOCALAPPDATA%\omp\omp.exe`），且 ≥ 18.4.11 |
| PATH 异常场景 | MSI 更新后重启的应用只有**机器级** PATH；`child_path.rs` 负责补回用户目录（#34） |
| Chromium | 非必需：面板自动发现；CI 用 `OMP_REQUIRE_CHROMIUM=1` 强制真实浏览器测试 |
| Linux 构建依赖 | `libwebkit2gtk-4.1-dev`、`libappindicator3-dev`、`librsvg2-dev`、`patchelf` |
| Node | JS 回归脚本无依赖；CI 用 Node 24 |
| Rust | stable 工具链；nightly 仅用于 clippy |

## 端口与网络

| 用途 | 绑定 |
|---|---|
| 远程访问 | `https://<interface IPv4>:<port>`，默认 7470；**只绑定所选网卡的 IPv4**，绝不 `0.0.0.0`/`::` |
| 浏览器代理占位端口 | `127.0.0.1:0` 随机分配；只接受同一 OS 用户的连接 |
| Chromium | **不监听任何端口**（`--remote-debugging-pipe`） |
