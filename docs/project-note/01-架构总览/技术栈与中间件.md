## 存储层（中间件替代品）

项目**没有数据库和消息队列**，状态全部落在文件 + 内存状态机：

| 存储 | 位置 | 实现 | 写入策略 |
|---|---|---|---|
| UI 偏好（tweaks） | `localStorage: omp-desktop:tweaks` | `design/tweaks/use-tweaks.js` | 即时 |
| 配置文件 | `<app config>/profiles.json`、`open-tabs.json`、`recent-projects.json`、`keybindings.json`、`terminal.json`、`browser.json`、`approval-mode.json`、`widgets.json`、`widget-approvals.json`、`remote.json`、`remote-devices.json` | `json_store.rs`（原子写 + 快照/回滚）、`config_file.rs`、`program_setting.rs` | 锁内提交，内存缓存 |
| 审批规则 | `<app config>/approval-rules/` | `approval.rs` `RuleBook` | session/project 两级 |
| 事件环 | 进程内存 | `agent/journal.rs`（256 条 / 8 MiB） | 按会话环形淘汰 |
| 终端输出环 | 进程内存 | `terminal/ring.rs`（1 MiB） | 整帧淘汰 |
| omp 自有数据 | `~/.omp/`（profile 见下） | omp 自身 | **只读**访问 `agent.db` |

**无 app config 目录时**：全部退化为**仅进程内存**，且刻意不回退到临时目录——否则另一个账户可以预先放一份 `open-tabs.json` 决定标签页在哪个文件夹启动。

**omp 的 profile 目录**：`~/.omp/agent/`（内置 profile，`PI_CODING_AGENT_DIR` 可覆盖）或 `~/.omp/profiles/<id>/`。`agent.db` 是 WAL 模式，只读打开、绝不 `immutable=1`、绝不 `SQLITE_OPEN_CREATE`、每次查询一个连接。

## 进程模型

| 子进程 | 谁启动 | 生命周期 |
|---|---|---|
| `omp --mode rpc-ui` | `agent/spawn.rs` | 每标签页一个；`close_tab` 结束，`stop_session` 重启 |
| headless Chromium | `browser/process/launch.rs` | 每标签页一个，懒启动；比 omp 活得久（切换 profile 不重置） |
| 用户 shell | `terminal/pty.rs` | 每标签页一个，首次打开终端面板才启动 |
| widget 插件 | `widgets/run.rs` | 按调度器触发，短暂运行，超时被杀 |
| `git` 二进制 | `workspace.rs` | 仅 stage/discard 时 |
| `omp <subcommand>` | `omp_cli.rs` | 一次性（统计面板、goal 配置） |

所有子进程都过 `spawn_gate.rs`：Chromium 启动期间排他持门，防止其它子进程继承 CDP 管道端。

## 版本闸

`MIN_OMP_VERSION = [18, 4, 11]`（`agent/spawn.rs:91`），用于会话树的 `fork`。应用**不按版本分支**：低于门槛直接拒绝启动并提示 `omp update`；只有通过结果被缓存。
