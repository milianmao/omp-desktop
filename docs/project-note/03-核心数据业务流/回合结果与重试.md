# 回合结果与重试

一次运行可能成功、失败、被自动重试、被用户中止，或在 agent 让出控制权后仍有后台任务。这个判定影响三处：标签页上的运行点、转录里的失败/重试行、以及"关闭忙碌标签页"的确认。

## 触发点

| 触发 | 帧 / 调用 | 说明 |
|---|---|---|
| 回合开始 | `agent_start`、`turn_start` | 置 `running` |
| 单条消息落定 | `message_end` | 记录 `stopReason`、`pendingFailure` |
| 回合让出 | `agent_end`（`yielded` 或 `isTerminal`） | 判定成功/失败 |
| 自动重试 | `auto_retry_start` | 建立 live-only 重试行 |
| 用户停止重试 | `OMP_BRIDGE.stopRetry` | `abort_retry`（等待期）或 `abort`（尝试中） |
| 后台任务 | `get_state.hasPendingAsyncWork` / `session_settled` | 置/清 `background` |
| 作业结果 | `async-result` 自定义消息 | 加 job 行 |
| 标签页激活 | `_initFetch` 的 `get_state` | 后台标签页的运行点在激活后刷新 |

## 数据流路径

```
omp 帧
  → live.js _handleEvent
     ├ agent_start / turn_start      → state.isStreaming = true
     ├ message_end                   → TURN 记录 stopReason；失败暂存 pendingFailure（omp 可能仍会重试）
     ├ auto_retry_start              → TURN 建 {kind:"retry", attempt, maxAttempts, phase}
     ├ agent_end
     │    · yielded / isTerminal 为真 → 结算：最后一条 assistant 若 stopReason=="error" → _showFailure
     │    · 继续进入下一次运行        → 不改动
     ├ prompt_result {agentInvoked:true, status:"error"} → 附错误文本 + retryable（"temporary" chip）
     ├ get_state.hasPendingAsyncWork  → state.asyncPending
     └ session_settled               → asyncPending = false
  → OMP_TURN_STATUS.runStateOf(state)
       失败 > 等待用户 > retrying > running > background > idle
  → TabRunDot / groupRunState（标签栏、分组 chip、侧栏）
  → OMP_SESSION_PREFS.isBusyRunState(runState) → confirmBusyClose 的确认条件
```

## 关键节点详解

| 节点 | 位置 | 核心逻辑 | 异常处理 |
|---|---|---|---|
| `runStateOf` | `app/turn-status.js` | 六级排序，`retrying` 也算 busy | 未知字段 → `idle` |
| 失败判定 | `turn-status.js` | `pendingFailure` 保留到 `agent_end` 让出控制才显示 | 未让出的 `agent_end` 不算结束 |
| 重试匹配 | `turn-status.js` | 被重试的气泡 = 最新带 `pendingFailure`/`aborted` 的 assistant 消息 | omp 自己决定是否接受输出（`producedOutput`） |
| 重试行 | `design/chat/retry-row.jsx` | 标题用 omp 的 `attempt`/`maxAttempts`，失败数用本地计数 | 仅 live-only，切标签后由 `get_messages` 重建 |
| Stop 按钮 | `live.js` `stopRetry` | 等待期用 `abort_retry`；尝试中（no-op）用 id-less `abort` | 阶段由 `phase` 决定 |
| job 行 | `turn-status.js` `finishedJobsOf` | 每个 job 一行，位于它触发的回复之上 | 无 omp 消息支撑 → 合并时保留原位，重启后消失 |
| 后台任务 | `live.js` | 每次 `agent_end` 与激活都查 `hasPendingAsyncWork` | 进程死 → `_endDeadProcessState` 清除 |

## 异常路径

| 异常 | 处理 |
|---|---|
| 请求失败但 omp 仍会重试 | 失败保持隐藏（`pendingFailure`），不提前吓用户 |
| 空停止（无产出） | omp 继续重试，前端不宣告成功 |
| 重试等待期按下 Stop | `abort_retry` 只取消睡眠，本轮以最后一次失败结束 |
| 尝试进行中按下 Stop | `abort_retry` 无效（实测），必须发 `abort` |
| 后台标签页的 `agent_end` | 未处理，直到激活后由 `get_state` 结算 |
| 后台任务尚未结束就重启 | 视为忙碌并确认（重启会杀掉该 job） |
| 切标签后失败块重建 | adapter 从 `get_messages` 重建 `errorMessage`，剔除 omp 的 `raw-http-request=` 行 |
| 桌面自造注记（无 `ts`） | 回退扫描时跳过，不会误当用户消息 |

## 关联组件

- 纯逻辑：`OMP_TURN_STATUS`（`runStateOf`、`groupRunState`、`isHidden`、`isBusyRunState`、`finishedJobsOf`）

- 命令：`abort`、`abort_retry`
- 组件：`design/chat/retry-row.jsx`、`chat/assistant-bubble.jsx`、`design/tab-group-chip.jsx`（`TabRunDot`）
