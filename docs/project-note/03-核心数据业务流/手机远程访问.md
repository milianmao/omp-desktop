# 手机远程访问

手机（同一局域网或 VPN）打开 `https://<host>:7470`，看桌面标签页、回答 agent 的问题、发送/引导/停止，并接收 Web Push。**默认关闭**，Settings → Remote access 打开前不监听任何端口。

## 触发点

| 触发 | 入口 | 说明 |
|---|---|---|
| 启用 | Settings → Remote access（`remote_apply_settings` 完整对象） | 绑定所选网卡的 IPv4 |
| 配对 | "Pair a phone…" → `remote_pair_start` | 128 位一次性码，5 分钟有效 |
| 手机连接 | 页面 `POST /pair` 或 WebSocket `/ws` 鉴权 | 设备 token（32 字节，仅存 SHA-256） |
| 手机动作 | `remote://action` → 桌面执行 → `remote_action_result` | 桌面 webview 仍是唯一事实源 |
| 推送 | 内部 tracker 变化 → manager 工作线程 | 阈值 30 秒；可选"仅锁屏时" |

## 数据流路径

```
手机页面 ⇄ TLS/WebSocket ⇄ Rust hub ⇄ Tauri 事件/命令 ⇄ 桌面 webview（发布者+执行者）⇄ OMP_BRIDGE ⇄ omp
                                  ▲
        agent stdout reader → tracker（全标签页 busy / 待答问题）→ 推送
```

- 桌面 webview **发布活动标签页的视图**（`remote_publish`，最多每秒 4 次）。
- 手机上的标签页**就是**桌面的标签页：在手机选中会激活桌面标签页。
- Rust 拥有传输、鉴权、证书、设置（`remote.json`）与设备（`remote-devices.json`，unix 上 0600）；webview 永远看不到 token 或私钥。
- 事件 Rust → webview：`remote://watch`（手机需要的标签页 id）、`remote://action`、`remote://status`。
- webview 在监听器就绪后才调用 `remote_ready(true)`；页面加载时 Rust 重置就绪状态，未就绪时以 4503 关闭手机 socket。

## 关键节点详解

| 节点 | 位置 | 核心逻辑 | 异常处理 |
|---|---|---|---|
| 绑定 | `remote/settings.rs` `DEFAULT_PORT = 7470` | 只绑所选网卡 IPv4，绝不 `0.0.0.0`/`::` | 接口消失 → 重绑或停止 |
| 接口枚举 | `remote/net.rs` | unix `getifaddrs`；Windows `GetAdaptersAddresses(AF_INET)` | 只列 up、非 loopback、非 wildcard |
| 配对 | `remote/pairing.rs` | 一次性码，内存态 | 每 IP 每分钟 5 次失败后 429 |
| 鉴权 | `remote/ws.rs` | 首帧 `{"t":"auth","token":…}`，5 秒内 | 否则 4401；每设备 4 socket、共 8 |
| 反 DNS rebinding | `remote/http/admission.rs` | `Host` 必须等于 `<ip>:<port>` 或 `<hostname>:<port>`；`Origin` 必须匹配 `https://…` | 其它一律 403，先于任何 handler |
| TLS | `remote/tls.rs` | 生成证书（SAN=当前 IP+主机名，2 年，带 `serverAuth`）或用户自带 PEM | IP/主机名变化、临近过期、手动"Regenerate"时重签 |
| Tracker | `remote/tracker.rs` | 每会话 `busy` / `turn_started` / 待答问题集合 | hook 必须 O(1) 非阻塞，sink 只入队 |
| 推送 | `remote/push*.rs` | 端点白名单（`push_subs.rs`），Web Push 走 `reqwest` blocker 线程 | 超阈值才发；"仅锁屏时"用 `remote/lock.rs` 探测 |
| 手机页 | `src/remote/*.js` | `client.js` 协议助手、`scanner.js` 摄像头、`sessions.js`、`transcript.js`、`remote.js` 协调 | — |

## 异常路径

| 异常 | 处理 |
|---|---|
| 配对链接过期/已用 | 已配对手机仍可用保存的 token 重连（0.12.0 修复） |
| 端口被占用 | 按 `ErrorKind` 判定并报错 |
| 接口 IP 变化 | 自动重绑或停止服务 |
| 证书不覆盖主机名 | 服务器拒绝启动并给出原因 |
| 自签证书下的首页 Web Push | 不可用（文档给出 mkcert + 局域网 DNS 处方） |
| 旧 `allowHttp` 设置 | 读取时忽略，下次保存时丢弃；无法启用明文 |
| 端口字段非法 | 回到已保存值，不在输入框里留下坏值 |
| 手机未就绪 | 以 4503 关闭 socket |
| 设备被撤销 | 4401 关闭，页面遗忘 token |
| tracker 收到重复 question id | 不重复开启（集合语义），每会话 64 上限 |
| omp 自己撤回对话框 | `cancel` + `targetId` 关闭该问题 |

## 安全模型

- 只有 TLS；配对码与 token 永不跨明文网络。
- 设备 token 只存 SHA-256，常数时间比较；webview 不接触。
- `Host`/`Origin` 校验在所有 handler 之前。
- 推送订阅只接受端点白名单内的 URL，绝不向白名单外的存储 URL 发送。
- 屏幕锁定探测：macOS `CGSession`、Windows `WTSQuerySessionInformationW`、Linux logind `LockedHint`（无锁屏上报的桌面按"未锁定"处理）。
