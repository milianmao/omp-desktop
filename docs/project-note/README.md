# OMP Desktop 项目知识库

`omp`（oh-my-pi CLI agent）的 Tauri 2 桌面外壳。一个标签页 = 一个 `omp --mode rpc-ui` 进程 + 一个 headless Chromium + 一个终端 shell；Rust 拥有全部策略与生命周期，`src/live.js` 是每标签页的状态机，React 只负责渲染。

**当前版本**：v0.12.1（2026-10-21）　**知识库版本**：KB-v1.0　**构建时间**：2026-10-25

## 十条必须先知道的硬约束

1. `omp --mode rpc-ui`，**不是** `--rpc`（后者退回 TUI，stdout 被 ANSI 淹没）。
2. 新 RPC 命令必须进 `ALLOWED_COMMAND_TYPES`，否则 `send_command` 拒绝。
3. 命令/技能必须走 `prompt` 帧（`streamingBehavior`），`steer`/`follow_up` 会跳过命令分发。
4. `close_tab` 是标签页的**唯一**终点；`stop_session` 只重启 omp，不碰浏览器与终端。
5. 桌面自造的转录条目**永不带 `ts`**（合并键是 `(kind, ts)`）。
6. `src/index.html` 的 script 顺序就是依赖图；新文件按依赖插入，不追加。
7. release CSP 是 `script-src 'self'`：不许内联事件处理器，不许 CDN。
8. Chromium 只有 `--remote-debugging-pipe`；任何端口都是禁忌。
9. 每次 widget spawn 前必须指纹校验，且执行已校验副本。
10. 新子进程一律过 `spawn_gate`；需要解析用户安装的二进制时过 `child_path`。
