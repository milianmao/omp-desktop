## 模块间交互矩阵

行＝发起方，列＝被调用方。`C` = Tauri command，`E` = Tauri event，`R` = omp RPC。

| 发起 ＼ 接收 | agent | browser | terminal | widgets | remote | git_browser | 存储 |
|---|---|---|---|---|---|---|---|
| `live.js` | C+R | C | C | C(视图状态) | C | — | C |
| `use-*.jsx` | 经 `OMP_BRIDGE` | 经 `OMP_BRIDGE` | 经 `OMP_BRIDGE` | E `widgets://*` | E `remote://*` | 经 `OMP_BRIDGE` | — |
| `agent/reader.rs` | — | — | — | 回调 `turn_ended` | 回调 `tracker().on_frame` | — | journal E |
| `start_session` | — | C `allocate` | C `register_tab` | C `session_started` | — | C `start_git_watch` | — |
| `close_tab` | C `stop_session` | C `release` | C `close_tabs` | C `session_closed` | — | C `stop` | — |

**关键点**：`start_session` 一次拉起四个子系统（omp 进程、浏览器条目、终端标签页注册、widget 会话、git 监视），`close_tab` 一次性拆掉它们。`stop_session`（profile 切换、审批模式重启）**只**重启 omp，其余保持。→ 详见 [会话全生命周期](../03-核心数据业务流/会话全生命周期.md)

## 职责边界上的三个反复出现的判断

1. **谁是"策略"**：能决定"跑什么程序/读什么路径/能否执行"的逻辑必须在 Rust。前端只送 id 与视图状态。
2. **谁是"状态"**：跨标签页必须存活的状态在 Rust（或 `live.js` 的 `sessionRegistry`）；纯 UI（草稿、折叠开关、面板宽度）在 React / `localStorage`。
3. **谁是"事实"**：omp 的队列、审批、模型、思考级别一律以 omp 的帧为准，前端**从不**本地编辑，只等下一帧覆盖。
