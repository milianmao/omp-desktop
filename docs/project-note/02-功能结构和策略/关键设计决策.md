# 关键设计决策

每条记录：**背景 → 决策 → 放弃的方案 → 代价**。这些是改代码时最容易被无意推翻的地方。

## D1 · 不重新实现 agent，只做外壳

**背景**：可能的方向是内嵌 agent 逻辑、或驱动 CLI。
**决策**：所有 agent 能力都来自 `omp --mode rpc-ui` 子进程；应用只做进程管理、渲染与桌面集成。
**放弃**：`omp --rpc` —— 会退化成 TUI，stdout 被 ANSI 淹没（AGENTS.md 明列为易踩点）。
**代价**：能力上限由 omp 决定；`MIN_OMP_VERSION` 需要随新 RPC 能力提升；omp 更新须在"应用不重启"下生效（因此只缓存成功的版本检查）。

## D2 · 每个标签页一个独立进程

**决策**：一个标签页 = 一个 omp 进程 + 一个 Chromium + 一个 shell，各自按标签页 id 归属。
**放弃**：单进程多会话（omp 的 `switch_session`）。
**代价**：内存与启动成本线性增长；换来的是崩溃隔离、每标签页独立 profile/cwd/审批模式，以及"改审批模式=重启一个标签页"这种简单语义（`_respawnSession`）。

## D3 · 无打包器，脚本顺序即依赖图

**决策**：`tauri dev` 直接服务 `src/`，JSX 由浏览器内的 Babel 编译；`src/index.html` 的 `<script>` 顺序是唯一依赖声明。
**放弃**：Vite/esbuild。
**代价**：每次 dev 启动多 ≈1.5 s 编译；顺序错误只表现为 `undefined`，无编译期提示；Babel 脚本共享顶层作用域，必须用唯一别名解构。
**收益**：零构建步骤即可调试源码；release 用同一份 vendored Babel 预编译，产物与 dev 行为一致。

## D4 · 所有依赖 vendored，禁止 CDN

**决策**：React/ReactDOM/Babel/marked/hljs/xterm/jsQR 全在 `src/` 内；release CSP 为 `script-src 'self'`。
**原因**：必须离线可用；CSP 收紧后 CDN 脚本根本无法加载。
**代价**：升级要跑脚本（`vendor-react.mjs`、`vendor-xterm.mjs`）或手工拷贝并提交；React 19 无 UMD，需脚本生成。

## D5 · Rust 拥有全部策略，webview 只发 id

**决策**：shell 路径、Chromium 路径、项目文件夹、审批模式都由 Rust 决定并持久化；webview 不发送任何用于 spawn 的路径。
**放弃**：把设置放 `localStorage`（更快，但 webview 一旦被注入即可改）。
**代价**：每个设置都要走一对 `*_set` / `*_pick` 命令；换来的是"信任边界只剩 webview 的 JS 完整性"这一条清晰假设。

## D6 · git 用 gix，不用 `git` 子进程

**决策**：读取（status/diff/log/graph/commit）全部用 gix；`git` 二进制只用于 stage/discard（`workspace.rs`）。
**原因**：避免 PATH 解析与文本解析两类脆弱性；也避免把仓库内容交给子进程。
**代价**：需要 `git_browser::open` 主动剥离仓库自身 config 的 filter driver（否则预览一个被解压的仓库会执行它的命令）；子模块不递归进入工作树。

## D7 · Chromium 只走 `--remote-debugging-pipe`

**决策**：不开 `--remote-debugging-port`；broker 独占管道，面板与 agent 都通过 broker 会话访问。
**原因**：调试端口对本机任意进程开放，等于把浏览器控制权交给同机任何程序。
**代价**：agent 需要一个代理端点 → 引入占位端口 + 同用户内核校验 + 请求准入（`Origin`/`Sec-Fetch-*`/`Host`）。Windows 上管道句柄可继承性迫使 spawn 门在 Chromium 启动期间排他。

## D8 · 远程访问从"可选明文"改为"仅 TLS"

**决策**：服务器只讲 TLS；旧的 `allowHttp` 设置被忽略并在下次保存时丢弃。
**证据**：`c0f64af feat(remote): tls only, drop the plain http switch`。
**原因**：配对码与设备 token 在明文 HTTP 下就是可嗅探的凭据。
**代价**：自签证书下首页 Web Push 不可用（需手机信任的证书），文档给出 mkcert 处方。

## D9 · 配置目录不可用时用内存，不用临时目录

**决策**：`app_config_dir()` 无法解析或是相对路径时，所有 store 退化为进程内存。
**证据**：`4dbed62 fix(config): keep stores in memory instead of the shared temp dir when the config dir is unresolvable`。
**原因**：临时目录是共享可写的，另一账户能预置 `open-tabs.json` / `widgets.json` / `terminal.json`，让应用按攻击者的选择启动标签页、命令或 shell。
**代价**：该次运行结束后设置不保留（这是刻意的）。

## D10 · journal + replay 而不是"总让 omp 重发"

**决策**：Rust 侧环形保存每会话最近事件，激活时按 `afterSeq` 重放；扩展 widget 额外在 Rust 保存一份快照。
**放弃**：只靠 `get_messages`（只有持久化文本，丢掉工具卡、审批气泡、流式状态）。
**原因**：omp 没有"查询当前 widget"的命令，重放窗口一旦滑出，被淘汰的 `setStatus`/`setWidget` 就永久丢失。
**代价**：内存上限（8 MiB/会话）与"dropped 后的已知残缺"。

## D11 · 审批模式变更用重启，不用 RPC

**决策**：`setApprovalMode*` 后对空闲标签页立刻 `_respawnSession`（`--resume`），忙碌标签页等到下一次 `get_state` 显示空闲再重启。
**原因**：omp 没有运行时改审批模式的 RPC；而 omp 默认是 `yolo`，继承它会静默放行一切。
**代价**：重启后 prompt cache 冷写一次（会话树会显示为"新进程冷价"）；未写入会话文件的标签页只能开新会话。

## D12 · 请求拒绝靠机械判据，而非"看起来像浏览器"

**决策**：代理请求准入检查 origin-form 目标、单一 `Host`（仅 `127.0.0.1`/`localhost`/`[::1]`）、禁止仅浏览器会发的头（`Origin`、除单独 `Sec-Fetch-Mode` 外的 `Sec-Fetch-*`）。
**原因**：DNS rebinding 与"本机网页偷偷驱动浏览器"是这类本地端点的两类经典攻击。
**代价**：规则需要跟着 puppeteer/Node 的实际请求头演进（注释记录了 `Sec-Fetch-Mode` 的例外来自 Node 的 `fetch`）。

## D13 · 危险默认必须显式覆盖

**决策**：
- `--approval-mode` 永远显式传给 omp（不继承 omp 的 `yolo` 默认）；
- 浏览器设置覆盖层永远带 `relay: false`（否则开了 relay 的用户会去驱动自己的 Chrome 而不是面板的）；
- `git_browser::open` 永远剥掉仓库级 filter driver；
- widget 插件永远先校验指纹再跑**副本**。

**共同模式**：上游的"便利默认"在这里全部被显式反转为安全默认，且写在代码常量的注释里。
