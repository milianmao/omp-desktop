# 设计模式与策略

本项目不追求设计模式目录，而是在几类**反复出现的约束**下形成了稳定的做法。下面按"这解决什么问题"组织。

## 一、进程与生命周期

### 1. 所有权下沉：一物一主

| 资源 | 唯一所有者 | 谁不能碰 |
|---|---|---|
| omp 进程 | 标签页 id（`sessionRegistry`） | 全局；没有"默认会话" |
| Chromium | 标签页 id | `stop_session` **不**释放它 |
| 终端 shell | 标签页 id（`TerminalManager` 注册表） | `stop_session` **不**关闭它 |
| widget 运行 | `RunKey { scope_key, plugin_id }` | 前端不持运行状态 |
| 审批授权 | 会话（`RuleBook` session 级）/ 项目 | 会话被替换时总清（`clear_session`） |

推论：`close_tab` 是**唯一**结束标签页的路径。新增"结束某物"的行为时，先问它属于哪一个所有者，再决定挂在 `close_tab`、`stop_session` 还是 `kill_child_processes`。

### 2. 分层拆解顺序：先杀，后等

`shutdown_all` / `close_tabs` / `release_many` 都是"先对所有对象发信号，再统一等待"。这样 N 个 shell 的 200 ms 挂断宽限只花一次，而不是累加 N 次。

**反例（不要这样做）**：`for x in xs { x.kill(); x.wait(); }`。

### 3. 双重保险：锁内清标志 + 锁外补偿

`AgentBridge` 的 `alive` 标志在 `sessions` 锁内被清（reader 线程可能正阻塞在同一把锁上，它一旦看到自己的表项消失就必须看到 `alive == false`）；`reap_and_clear_grants` 里再清一次作为幂等兜底。**注释明确写了"这是冗余的安全网，不是唯一清除点"**——这类"看起来重复但顺序有语义"的代码不要简化。

### 4. 子进程一律过门

`spawn_gate.rs` 是所有子进程的创建入口：
- `spawn` / `output` / `status`：直接可用；
- `shared()`：为"不是我们创建"的 spawn 加护栏（portable-pty、`open`、gix）；
- `exclusive()`：Chromium 启动期间排他——因为 Windows 会把**所有**可继承句柄交给此刻创建的任何子进程，macOS 要等 pipe 创建后才设 close-on-exec。若此处漏掉，任何子进程都能绕过 broker 摸到 CDP 管道。
- `clippy.toml` 的 `disallowed-methods` 会在本地 clippy 中拦住绕过门禁的 `Command::spawn`。

## 二、协议与状态同步

### 5. 快照 + 增量补偿（journal + replay）

前端只处理活动标签页的帧。后台标签页的帧被 Rust 的 `EventJournal`（256 条 / 8 MiB 环形）收着；激活时 `replay_events(afterSeq)` 补齐，`dropped: true` 表示窗口已滑出（此时靠 `get_messages` 恢复文本、靠 `extension_ui_state` 恢复扩展卡片）。

### 6. 幂等重放 + 代际守卫

每次激活都有 `_switchGen`（代际号）。所有异步步骤后都检查 `current()`，一次"被更新激活取代"的旧流程会静默退出而不污染新标签页。**没有这个检查，一次慢的 `unlisten` 就能把 A 标签页的审批提示投进 B 标签页。**

### 7. omp 是唯一事实源

队列、模型、思考级别、goal、子 agent、扩展 widget 一律"等 omp 的下一帧覆盖"，从不本地编辑。前端的乐观更新只用于**自己的**产物（草稿、队列条里"发送中"那行），且必须能被 omp 的帧收走。

### 8. 按 `ts` 合并，不按位置

`mergeTranscript` 用 omp 消息的 `timestamp` 匹配实时条目与 `get_messages` 持久副本。位置配对在双方顺序出现分歧时会让后面所有条目错位。桌面自造条目**永不带 `ts`**。

## 三、安全

### 9. 内核态/文件系统校验优先于应用层检查

| 场景 | 做法 |
|---|---|
| 浏览器代理端口 | 连接线程先查对端 socket 的**属主 UID**（Linux `/proc/net/tcp`、Windows `GetExtendedTcpTable` + 进程创建时间 + token SID、macOS `lsof`），不是看请求头 |
| 文件预览越界 | `project_file_read` 在路径字符串校验之后再 canonicalise **目标文件**，符号链接逃逸返回 `Outside` |
| git 过滤驱动 | `git_browser::open` 在内存中删除仓库自身 config 定义的 `filter` 段，只保留用户/系统/环境级 |
| widget 插件 | 每次 spawn 前校验指纹，并执行**已校验的副本**（`widgets/snapshot.rs`），不是校验后跑原路径 |

**共同点**：不信任"上层已经检查过"。

### 10. 严格 CSP + 唯一渲染防线

release 的 `script-src 'self'` 让内联事件处理器无法执行；`app/marked-setup.js` 把**所有**原始 HTML（块级与行内）转义成文本，是 `tauri dev`（仍有 `'unsafe-inline'`）下唯一防线。不做标签白名单、不手写 sanitizer——标记语言的边界情况比白名单多。

## 四、缓存与性能

### 11. 三条独立流控

| 通道 | 水位 | 阻塞点 |
|---|---|---|
| 终端输出 | 未 ack 512 KiB（HIGH_WATER），降到 128 KiB（LOW_WATER）才恢复 | pump 停止出帧并停止排空队列 → reader 阻塞 → pty 反压 shell |
| 浏览器帧 | 面板未 ack | 同上模式（screencast 流控） |
| widget 输出 | stdout 上限 + 超时 | 运行被终止 |

**共同点**：宁可让被观测的进程变慢，也不让 IPC 队列无限增长。

### 12. 分级计算成本

子 agent 订阅三档（`off` / `progress` / `events`），最贵的 `events` 只在检查器里真的显示某个运行中 agent 时使用，且离开标签页前先降级。

### 13. 有界一切

| 对象 | 上限 |
|---|---|
| 事件 journal | 256 条 / 8 MiB |
| 终端输出环 | 1 MiB |
| 扩展状态键 / 值 | 32 键、键 200 字节、状态 4 KiB、行 50 条 |
| 打开的审批提示 | 每会话 64 |
| 打开的远程问题 | 每会话 64 |
| 远程连接 | 每设备 4、共 8 |
| 浏览器代理连接 | 并发 32、未审核 32 |
| git 浏览器 | 20 000 文件、提交/行/字符各有上限 |
| widget 并发运行 | 4 |

## 五、错误与降级

### 14. 状态机里"退化为默认值"要留下痕迹

配置文件读不出来时：读到默认值 **+ 记日志 + 拒绝写入**（`program_setting`、`approval_mode` 共用同一策略）。这样用户不会因为一次解析失败就静默丢失自己的设置。

### 15. 失败要说真话

- `start_session` 失败的错误被缓存，`session_status` 可主动查询，`send` 也会优先返回它（而不是 "session not found"）。
- 启动瞬间就死掉的子进程，reader 用**有界的 stderr 尾部**替代空 payload，避免把崩溃读成"正常退出"。
- 历史报错里的凭据经 `redaction.rs` 统一打码（reader 与 widget 共用同一份键表）。

### 16. 不做"看起来更聪明"的回退

- 配了但已失效的 shell/Chromium 路径 → **报错**，不悄悄换一个。
- omp 版本低于闸门 → **拒绝启动**，没有降级分支。
- 远程访问要求 TLS，`allowHttp` 旧设置被忽略而非启用明文。
- 没有 app config 目录 → 内存模式，**绝不**回退到临时目录（另一账户可预置文件）。
