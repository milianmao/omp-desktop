## 近期版本要点（0.7.0 → 0.12.1）

### 0.7.0 — rail 成为插件宿主
- 等待中的 steer / follow-up 加 ⚡ 按钮，立即中断当前 step 并继续（#47）。
- 拖图片到 prompt box 即附件；窗口其他位置的 drop 被拒绝（#50）。
- `/collapse-all`、`/expand-all` 一键折叠或展开全部工具卡与 thinking（#43）；thinking 与 tool output 各自可选 auto/open/folded。
- rail widget 插件（#49）：`<app config>/widgets.json` 列程序，stdout JSON 渲染为卡片，脚本未批准不运行。
- omp extension 的 `setStatus`/`setWidget` 落入 rail（#52）；rail 卡片可逐个隐藏并跨重启保留（#51）。

### 0.8.0 — 每 tab 一个 shell
- 终端面板与状态栏按钮、`Ctrl+\``、`/terminal` 打开，cwd 为 tab 项目目录，隐藏面板不结束进程（#56）。
- 输出快于绘制时减速（背压），关 tab 结束整棵进程树，`exit` 后回车重开。
- 高度可拖拽并持久化。

### 0.9.0 — 审批模式与 git browser
- 审批模式（#57）：`always ask` / `write`（默认）/ `yolo`，全局默认 + 每项目覆盖；变更会重启受影响的 omp，忙碌 tab 在回合结束时切换。
- git browser 三栏（文件 / 全文内联 diff / 提交历史），读操作改用 gix，staging 仍走 `git` 二进制。
- 状态栏移除 model/thinking，git 按钮改为打开 git browser。
- 草稿中 ↑/↓ 只移动光标，历史召回仅在空 prompt box（#55）。

### 0.10.0 — 浏览器面板
- 与 agent 共享的 Chromium 面板：跟随页面、页 tab、地址栏、全屏视图，标注以文本 + 截图进入下一条消息（#58）。
- conversation tree 与浏览器面板一样按 tab 记忆开合；状态栏改为横贯窗口底部单行，空间不足时按 tokens/s → cost → context 顺序丢格。
- 图标随字号缩放；带引号的 `terminal.json` shell 路径可用。

### 0.10.1 — macOS 分发修复
- 浏览器下载的 `.app` 不再报 "is damaged and can't be opened"（#60）；改为 ad-hoc 签名，仍未公证。

### 0.11.0 — Settings 统一入口
- Settings 作为 tab 打开（#37），覆盖 Appearance/Layout/Chat/Composer/Rail/Terminal/Browser/Agent/Session/Approvals/Shortcuts，带搜索与"已改动"标记；Tweaks 面板与 `/tweaks` 移除。
- 可拖拽列宽（#41）：对话与侧边栏/子代理/rail/conversation tree 之间，宽度持久化，双击复位。
- 文件预览（#39）：read 卡路径与回复中的项目文件链接，行范围高亮、图片缩略、"Open in git browser"。
- 安全修复集中发布：git filter 执行、空/相对 `PATH` 条目导致的 `omp`/`git` 劫持、审批规则串 tab、widget 脚本 approval 后替换、Chromium 调试端口、spawn 继承调试管道、配置目录缺失时退回共享临时目录。

### 0.12.0 — 手机远程访问
- 远程访问整体落地：局域网/VPN 内读取 tab、回答 ask、send/steer/stop、推送通知；TLS 证书、一次性二维码配对、设备列表与撤销；默认关闭。
- 强制 HTTPS，旧的 `allowHttp` 被忽略；手机端打开会话即跳到最新并显示 "↓ Newest"。
- rail widget：`"attention"` 键驱动边框脉冲 + dock 图标跳动 + "Acknowledge"；`"insert"` 可把条目送进指定文件夹的新 tab 草稿。
- 修复 macOS 子进程被内核丢弃本地网络连接（`NSLocalNetworkUsageDescription`）；窗口最小尺寸降到 480×320。

### 0.12.1 — 锁屏通知
- Settings → Remote access → Notifications 增加 "Only while the desktop is locked"（默认关）；Linux 依赖向 systemd-logind 汇报锁屏的 locker（GNOME、KDE Plasma 满足）。

## 版本号机制

发布由用户触发（"release X.Y.Z"），步骤见 `AGENTS.md` 的 **Changelog workflow** → 详见 [Git工作流与CI](../05-项目开发规范/Git工作流与CI.md)。

必须同时对齐的四处：

| 位置 | 要求 |
|---|---|
| `CHANGELOG.md` | `## [Unreleased]` 改名为 `## [X.Y.Z] - YYYY-MM-DD`，上方插入新的空 `## [Unreleased]` |
| `src-tauri/Cargo.toml` | `version = "X.Y.Z"`（当前 0.12.1） |
| `src-tauri/tauri.conf.json` | `"version": "X.Y.Z"`，必须与 tag 一致 |
| `src-tauri/Cargo.lock` | `cargo update --manifest-path src-tauri/Cargo.toml --package omp-desktop` |

发布提交为 `chore: release vX.Y.Z`，随后 `git tag vX.Y.Z`、`git push origin master --tags`。

`dist/` 的版本戳与上面同一来源：`scripts/build-frontend.mjs` 读 `src-tauri/tauri.conf.json` 的 `version`，给 `dist/index.html` 的每个 `<script src>` / `<link href>` 和 `dist/**/*.css` 的 `@import` 加 `?v=<version>`。原因：Windows 上 WebView2 数据目录（`%LOCALAPPDATA%\<identifier>\EBWebView`）在应用内更新后依然保留，而 Tauri 内嵌资源响应不带 ETag/Last-Modified/Cache-Control，同名 URL 会被旧版本 HTTP 缓存命中，load-order 依赖图可能混跑新旧模块（0.4.0 之后真实出现过）。版本号每次发布都变，因此戳出的 URL 必然 miss。该校验同时 fail-closed：`tauri.conf.json` 的 version 必须是纯 semver 字符串，否则构建失败。细节 → 详见 [部署与运行架构](../01-架构总览/部署与运行架构.md)。

发布流水线侧：`.github/workflows/release.yml` 先跑 `tests.yml`，再逐平台签名构建，最后由 `.github/scripts/updater-json.mjs` 汇总 `latest.json`（用本 changelog 对应版本小节作 release notes）；feed 缺平台、或 tag 与应用版本不一致时拒绝发布。签名私钥只存在于 `TAURI_SIGNING_PRIVATE_KEY` 仓库 secret，绝不入库。
