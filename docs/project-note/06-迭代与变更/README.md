# 06 · 迭代与变更

本分类回答"这个项目走到哪了、踩过什么坑、知识库本身什么时候改过"。

| 文档 | 一句话摘要 | 什么时候读 |
|---|---|---|
| [版本历史](版本历史.md) | 0.1.0 → 0.12.1 全部发布的表格（版本/日期/主题/主要新增/主要修复）、近六个版本要点、版本号机制与 `?v=` 缓存戳的由来 | 定位"某功能是哪版加的"、准备发版 |
| [已知问题与陷阱](已知问题与陷阱.md) | 38 条陷阱，分五组（构建与打包 / 前端加载与 CSP / RPC 协议与状态同步 / 进程与资源 / 安全边界），每条含现象、根因、规避、证据（path:line 或 commit）；末附症状速查表 | 动手前预防、排查诡异现象、评审时确认"这行注释为什么在" |
| [变更日志](变更日志.md) | 知识库自身的每次更新记录（KB 版本号、新增/更新/删除、触发原因） | 判断知识库是否过期 |

## 用法

- **排查 bug 前**：先查 [已知问题与陷阱](已知问题与陷阱.md) 的症状速查表，再看对应分组的条目。
- **改动架构前**：对照 [关键设计决策](../02-功能结构和策略/关键设计决策.md)，确认不是在推翻一条有理由的决策。
- **发版**：按 [版本历史](版本历史.md) 的"版本号机制"一节，四个文件必须一致。
