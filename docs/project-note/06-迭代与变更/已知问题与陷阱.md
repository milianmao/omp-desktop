# 已知问题与陷阱

每条陷阱都来自 AGENTS.md「Things easy to break」、`docs/architecture/*.md` 的 Not covered / Limits / Security 小节、或一次真实的 `fix(...)` 提交。**证据**列给出可复查的 `path:line`、commit sha 或文档小节。

## 构建与打包

### `omp --rpc` 会落回 TUI
- **现象**：每个 tab 起来后界面一片 ANSI 转义乱码，没有 JSON 帧，前端收不到任何事件。
- **根因**：omp 的 `--rpc` 不是 RPC 模式开关，`omp` 走默认 TUI 路径，向 stdout 打屏。
- **规避**：只用 `--mode rpc-ui`，且必须是**两个 token**（`"--mode"`、`"rpc-ui"`），不是 `--mode=rpc-ui`。
- **证据**：`src-tauri/src/agent/spawn.rs:238`；`AGENTS.md:188`

### 更新后 omp 找不到（MSI 重启 / macOS GUI 最小 PATH）
- **现象**：应用内更新后自动重启，所有 tab 空白、无任何报错，手动重启又正常。
- **根因**：MSI 的 `LaunchApplication` 自定义动作由 Windows Installer 服务启动，子进程只继承**机器级** PATH，用户级安装（`%LOCALAPPDATA%\omp`）不在其中；macOS 从 Finder/Dock 启动只给 `/usr/bin:/bin:/usr/sbin:/sbin`，Homebrew 路径缺失。
- **规避**：`child_path::child_path()` 从注册表/常见安装目录补 PATH 后追加（继承项仍在前），omp 与 git 都经它 spawn。
- **证据**：commit `9ea26ea`（#34）、`310a0b9`；`src-tauri/src/child_path.rs:10-14`；`CHANGELOG.md:195`、`CHANGELOG.md:346`

### 相对 PATH 条目让项目自带的 `omp`/`git` 被执行
- **现象**：安全审计发现"打开某项目即可能执行该项目里的 `omp`"——以用户权限运行任意代码。
- **根因**：裸名 `omp` 会在**项目目录**解析，PATH 里的 `.` / `bin` / `::` 让项目自带可执行文件抢先命中。
- **规避**：omp 与 git 都只在**绝对** PATH 目录里查找、按绝对路径 spawn，并把 PATH 去掉相对条目后交给子进程；`Command::spawn/output/status` 被 `clippy.toml` 禁用。
- **证据**：commit `f7fc3b6`、`ae0e626`；`src-tauri/src/agent/spawn.rs:20-30`；`src-tauri/clippy.toml:5-9`；`CHANGELOG.md:60`

### Linux `.desktop` 少了 `%F`：右键"打开方式"打开空应用
- **现象**：文件管理器里对文件夹选"用 OMP Desktop 打开"，应用起来但没有 tab。
- **根因**：Tauri Linux 模板给的是裸 `Exec={{exec}}`，用户选的文件夹进不了 argv；`MimeType` 行缺失则应用直接从菜单里消失。
- **规避**：`omp-desktop.desktop` 必须保留 `Exec={{exec}} %F` 与 `MimeType=inode/directory;{{#if mime_type}}{{mime_type}};{{/if}}`——两半都不能删。
- **证据**：`src-tauri/packaging/omp-desktop.desktop:21`、`:27`；`AGENTS.md:207`

### MSI 目录动词写进 `Wow6432Node` / 标签漂移
- **现象**：64 位资源管理器里看不到"Open with OMP Desktop"；或改名 `productName` 后菜单标签仍是旧名。
- **根因**：预处理器 `define` 不跨 `.wxs` 文件，`Win64` 必须在该文件里重新推导，否则组件按 32 位安装写到 `Wow6432Node`。
- **规避**：保留 `<?define Win64 = "no"/"yes" ?>` 条件块，并让注册表 `Value` 与 `productName` 保持同步。
- **证据**：`src-tauri/packaging/windows-folder-verb.wxs:17`、`:22-24`、`:33`；`AGENTS.md:208`

### 非 UTF-8 参数让应用启动即崩
- **现象**：Linux 上对一个非 UTF-8 名字的文件夹"打开方式"，进程直接 panic，而不是记录一条被丢弃的请求。
- **根因**：`std::env::args()` 在非 UTF-8 参数上 panic，而目录名是任意字节串，`%F` 原样传入。
- **规避**：冷启动 argv 摄取必须留在 `args_os()` + lossy 转换；注意转发路径仍受插件限制（`tauri-plugin-single-instance` 的**发送方**自己用 `args()`）。
- **证据**：`src-tauri/src/lib.rs:1402`、`:1417`；`AGENTS.md:209`

### 单实例插件顺序 / macOS 双重处理
- **现象**：第二次启动开了两个窗口；或 macOS 上双击文件夹启动两个实例互相抢。
- **根因**：`tauri-plugin-single-instance` 必须在 `Builder` 里**第一个**注册；且 macOS 的 `LaunchServices` 自己就复用实例，插件会与之打架。
- **规避**：保持 `cfg` 到 Windows/Linux，且 `builder.plugin(single_instance_plugin())` 在其它插件之前。
- **证据**：`src-tauri/src/lib.rs:1478`、`:1482`；`AGENTS.md:205`

### 更新后前端新旧文件混跑（`?v=` 缓存戳）
- **现象**：0.4.0 之后的真实故障——选完文件夹但没有 tab 出现，直到 WebView2 缓存偶然淘汰才恢复。
- **根因**：`%LOCALAPPDATA%\<identifier>\EBWebView` 在更新后存活，而 Tauri 内嵌资源响应不带 ETag/Last-Modified，同名 URL 会命中上一版本的 HTTP 缓存，加载顺序图被拆成一半旧一半新。
- **规避**：`build-frontend.mjs` 给 `dist/index.html` 的每个 script `src`/stylesheet `href` 和 `dist/**/*.css` 的 `@import` 打 `?v=<version>`；版本号取自 `tauri.conf.json`，故发布时必须升版本。
- **证据**：commit `e42e64c`；`scripts/build-frontend.mjs:26-31`、`:152-162`；`docs/architecture/release-frontend.md:5`；`CHANGELOG.md:212`

## 前端加载与 CSP

### 两份 CSP 必须只差一个 token
- **现象**：`npm run build` 直接抛错：`tauri.dist.conf.json: app.security.csp must be tauri.conf.json's minus script-src 'unsafe-inline'`。
- **根因**：dev 变体含 `'unsafe-inline'`（Babel 把编译结果当内联 `<script>` 跑），release 变体必须是 `script-src 'self'`；脚本按"减去该 token"来推导期望值。
- **规避**：只能成对修改 `tauri.conf.json` 与 `tauri.dist.conf.json`；两者都不能加 `'unsafe-eval'`（无人使用 `eval`/`new Function`）。
- **证据**：`src-tauri/tauri.conf.json:12`、`src-tauri/tauri.dist.conf.json:9`、`scripts/build-frontend.mjs:136-143`；`AGENTS.md:199`

### Tauri 的 CSP hash 注入会静默抑制 `'unsafe-inline'` → 黑屏
- **现象**：窗口一片黑，React 从未挂载，控制台报脚本被 CSP 拒绝。
- **根因**：CSP Level 2 规定 `script-src` 里出现 hash 时 `'unsafe-inline'` 被忽略；Tauri 为 `withGlobalTauri` 注入的初始化脚本会带 SHA-256。
- **规避**：`:13` 的 `dangerousDisableAssetCspModification: true` 不能去掉；同时不要引入 CDN（历史上 Google Fonts 也参与过黑屏）。
- **证据**：commit `d45ce00`；`src-tauri/tauri.conf.json:13`；`CHANGELOG.md:396`

### 内联事件处理器在 release 里是死的
- **现象**：dev 正常，打包后代码块复制按钮点了没反应。
- **根因**：release `script-src 'self'` 禁止内联 `onclick`；`marked-setup.js` 的 `code` 渲染器只能产出无 handler 的标记。
- **规避**：交互走容器上的 `onClick` 委派（`copyCodeBlockClick` 解析按钮再复制 `<code>` 的 `textContent`）；`build-frontend.mjs` 会拒绝 `dist/index.html` 里的内联 `<script>` 与 `on*` 属性。
- **证据**：`scripts/build-frontend.mjs:113`、`:116`；`AGENTS.md:201`

### Markdown 里的原始 HTML 必须整体转义（两个渲染器）
- **现象**：`<img onerror=…>` 在 dev 下真的执行（dev CSP 仍是 `'unsafe-inline'`）；或修好后整段末尾的 `&` 变成 `&amp;` 字面量。
- **根因**：`dangerouslySetInnerHTML` 注入的是暴露 `window.__TAURI__` 的 origin；而 inline `<pre>`/`<code>`/`<script>` 还会把 marked 的 lexer 推进 raw-block 模式，其 text token 带**未转义**原文，默认 text 渲染器会原样输出。
- **规避**：`marked-setup.js` 同时覆写 `html` 与 `text` 两个渲染器，`escaped: true` 的 token 走 `escapeKeepingRefs`（保留 `&…;` 引用）；不要改写成标签白名单或手写 sanitizer。
- **证据**：`src/app/marked-setup.js:51-52`、`:96-102`；`src/design/ui/markdown.jsx:36`；`AGENTS.md:200`

### 固定三反引号围栏被正文里的围栏提前闭合
- **现象**：被拒绝的消息之后的正文整段变成 Markdown 渲染（标题、加粗全生效）。
- **根因**：`failureNote` 把任意文本包进围栏；固定 ```` ``` ```` 会被文本自身的围栏行闭合。
- **规避**：一律用 `OMP_MARKDOWN.fenceCode`，它生成比正文最长反引号串更长的围栏。
- **证据**：`src/app/marked-setup.js:30`；`src/app/message-queue.js:92`；`AGENTS.md:202`

### 脚本顺序即依赖图，且 Babel 脚本共享一个顶层作用域
- **现象**：某个纯 IIFE 模块的 `window.*` 未定义（`Cannot read properties of undefined`），或两个 `.jsx` 的顶层 `const Icon` 互相覆盖。
- **根因**：`text/babel` 脚本共享同一顶层作用域；多处 JSX 在**顶层解构**全局（而非调用时读取），所以顺序错一位就炸。
- **规避**：新增文件前先在 `frontend-load-order.md` 里定位；跨文件同名解构必须用唯一别名（`_GT_`/`_SV_`/`_TP_` 之类）。
- **证据**：`docs/architecture/frontend-load-order.md:6`、`:29`

### 窗口控件依赖 `querySelector` 会变成时序赌博
- **现象**：`tauri dev` 里窗口按钮能用，release 里全失效（或反之）。
- **根因**：React 挂载相对 `DOMContentLoaded` 的先后在两种构建里相反——dev 在之后，release `dist/` 在之前。
- **规避**：窗口控件用**文档级** click 委派；`live.js:4566` 的 `DOMContentLoaded` 分支只是兜底。
- **证据**：`src/live.js:3029`、`:4566-4568`；`AGENTS.md:193`

### 手机页面必须先加载 highlight 再加载 marked-setup
- **现象**：手机上助手回复里的原始 HTML 被真的渲染进一个**持有设备 token** 的页面。
- **根因**：`marked-setup.js` 开头有 `if (!window.marked || !window.hljs) return;`，缺 hljs 时整个转义层不安装。
- **规避**：`src/remote/index.html` 里 `/highlight.min.js` 必须在 `/marked-setup.js` 之前。
- **证据**：`src/remote/index.html:19-20`；`src/app/marked-setup.js:49`；`AGENTS.md:211`

### 旧版 WebView 下 CSS 静默降级
- **现象**：Windows 上状态栏在最窄宽度下不折叠，只是被裁掉一行；或毛玻璃/边框色整块丢失。
- **根因**：`color-mix(in oklab, …)` 需要 WebView2 ≥ 101，状态栏的窄宽折叠用容器查询，需要 WebKitGTK ≥ 2.40 / WebView2 ≥ 105。旧 webview 不报错，只是忽略这些规则。
- **规避**：改这些样式时按上述版本下限验收；不要用 JS 特性检测替代——失效形式是"看起来能用"。
- **证据**：`src/platform.css:61`、`src/design/layout/rail.css:28-30`；`AGENTS.md:198`

### vendored 库禁止手改，也不许引 CDN
- **现象**：手改 `src/xterm.js` 或 `src/remote/jsQR.js` 后，下次 `scripts/vendor-xterm.mjs` 覆盖即丢；或加了 CDN 标签后离线/内网环境白屏。
- **根因**：所有前端库都是入库的（应用必须离线可用），且 xterm 由脚本从 npm 重新生成——`.js` 只保留 `/*!` 版本 + MIT banner，`xterm.css` 原样；jsQR 是 `jsqr@1.4.0` 的未压缩 webpack UMD 构建，header 记着版本与 SHA-256。
- **规避**：升级只能重跑脚本或重跑 `npm pack`，不能编辑库体；新增库同样入库，不加 CDN，也不要 `convertFileSrc()`（asset protocol 已禁用）。
- **证据**：`src/xterm.js:1-2`；`scripts/vendor-xterm.mjs:1-12`；`src/remote/jsQR.js:1-5`；`AGENTS.md:204`；`src-tauri/tauri.conf.json:14-17`

## RPC 协议与状态同步

### 用 `reader.lines()` + 通配 `_ => break` 会被第一个空行杀掉
- **现象**：agent 第一条空行之后所有事件消失，tab 变哑巴；stderr 也没有原因。
- **根因**：`lines()` 把"读到 0 字节（EOF）"与"读到空行"混为一谈，通配分支把空行当成管道关闭。
- **规避**：`agent/reader.rs` 用 `read_until_capped` 显式区分 `Ok((0, _))`（EOF）与空行，并自行剥离 CR/LF。
- **证据**：`src-tauri/src/agent/reader.rs:300-320`；`AGENTS.md:192`

### `abort()` 必须保持 **id-less**
- **现象**：按 Esc 停不了 turn；或 goal mode 的"用户暂停"标签永远不消失，自动改名的一次性预算再也不恢复。
- **根因**：`_handleResponse` 里"有 pending id 就先按 id 分发并 return"的分支在 `abort` 分支之前，带 id 的 abort 响应永远到不了 `abort` 分支，`userAbortInFlight` 无法释放。
- **规避**：`abort` 不带 id；`userAbortInFlight` 由它的响应清除，`_releaseAutoRenameAfterAbort` 也依赖这条调用点。
- **证据**：`docs/architecture/session-title.md:9`；`src/live.js:114`、`:1558-1562`；`docs/architecture/goal-mode.md:7`；`docs/architecture/message-queue.md:10`

### `set_model` 响应不立刻 `notify()`，UI 会回滚
- **现象**：切换模型后界面闪回旧模型，直到下一个 turn 才开始显示新模型。
- **根因**：`state.model` 的更新依赖 `notify()` 推出，下一个 `turn_start` 会带上 omp 侧的 `state.model`（旧值）覆盖。
- **规避**：`set_model` 分支里改完 `state.model` / `state.models` 立即 `notify()`。
- **证据**：`src/live.js:2024-2029`；`AGENTS.md:194`

### tab 切换后的 transcript 合并要按 omp 消息匹配，不能按位置
- **现象**：切一次 tab 回来，气泡错位、卡片/备注/job 行整体下移一格。
- **根因**：live 侧存在 omp 永远不会返回的条目（卡片、备注、job 行、适配器跳过的气泡），而 omp 又会自己丢掉消息（重试的尝试、拒绝、空 turn），位置配对一旦错开就全错。
- **规避**：用户/助手条目带 omp 的 `timestamp` 作为 `ts`，按 `kind:ts` 配对；**桌面自造条目绝不能带 `ts`**。
- **证据**：`src/app/transcript-merge.js:1-12`、`:27`；`AGENTS.md:197`；commit `42fd30c`

### `_handleResponse` 的长 `if/else if` 链少一个 `}`
- **现象**：整个前端不工作，`window.OMP_DATA` 从未设置；控制台只报 IIFE 语法错误。
- **根因**：单个错位花括号让 `_handleResponse` 永不闭合，整个 IIFE 语法错误——错误位置与真实改动点相距很远。
- **规避**：插入新分支后必须重新校验括号结构。
- **证据**：`AGENTS.md:196`；`src/live.js`（`_handleResponse`）

### 命令与 `/skill:` 调用必须走 RPC `prompt`，不能走 `steer`/`follow_up`
- **现象**：`/compact`、`/skill:xxx` 发出去了但什么都没发生（甚至被当成普通文本塞给模型）。
- **根因**：omp 的 `steer` / `follow_up` 帧**跳过**命令分发与 skill 分发；中途发送必须用 `prompt` + `streamingBehavior`。
- **规避**：分类只由 `OMP_SLASH.isCommandInvocation` 一个谓词决定（前导已知命令，或草稿中任意位置 omp 会调用的 `/skill:<name>`），且分类对象是**用户输入的草稿**，不是合并浏览器标注之后的文本。
- **证据**：`src/app/slash-commands.js:329`、`:344`；`AGENTS.md:195`

### 浏览器设置 overlay 必须是最后一个参数且只影响浏览器
- **现象**：用上浏览器面板后，tab 的审批策略莫名变了，或 profile/resume 设置被替换。
- **根因**：`omp_args` 里 `--config=<path>` 若穿插在别处会改变后续 flag 的归属；overlay 里若写全量设置就会覆盖 tab 自己的 profile 配置。
- **规避**：`--config=` 固定在 `--cwd=`、`--profile`/`--resume`、`--approval-mode=<mode>` **之后**追加；overlay 只写 `browser.cdpUrl` 加 `browser.relay: false`（防止已开启的 omp relay 反超面板浏览器的优先级）。
- **证据**：`src-tauri/src/agent/spawn.rs:250-256`、`:563`（`omp_args_appends_config_last`）；`AGENTS.md:189`

## 进程与资源

### 绕过 `spawn_gate` 不会在 CI 被拦住
- **现象**：本地 clippy 通过、PR 也绿，但引入了绕过 spawn gate 的子进程。
- **根因**：`clippy.toml` 的 `disallowed-methods` 只在 `cargo +nightly clippy` 本地运行时生效，**CI 不跑 clippy**。
- **规避**：只能靠 `AGENTS.md` 的 verify 命令与人工 review；Chromium CDP 管道端的可继承句柄只在那把门里安全。
- **证据**：`src-tauri/clippy.toml:5-9`；`docs/architecture/browser.md:221`；`AGENTS.md:223`

### 更新器重启路径不跑 `Drop`，漏掉 `kill_all` 就孤儿进程
- **现象**：点"重启并更新"后旧的 widget 插件、Chromium、终端 shell 还活着。
- **根因**：更新器 relaunch 不经过托管状态的析构；Unix 上每个进程树在自己的进程组/会话里，会活得比我们久。
- **规避**：`kill_child_processes` 里必须保留 `widgets::kill_all(app)` 在 `AgentBridge::shutdown_all()` 旁边，并在 `RunEvent::Exit` 也调用。
- **证据**：`src-tauri/src/lib.rs:1219-1230`、`:1593`；`docs/architecture/widgets.md:219`

### Chromium 冷启动可能赶不上 omp 的 5 秒 CDP 等待
- **现象**：浏览器面板第一次给 agent 调用报 CDP 连接失败，第二次就好了。
- **根因**：omp 等 CDP 端点 5 秒，而冷启动 Chromium 的最长启动超时是 10 秒。
- **规避**：接受"首次调用可能失败"为已知行为；不要为此加 `--remote-debugging-port` 或任何旁路（占位端口是唯一监听者，且按 OS 用户校验对端）。
- **证据**：`docs/architecture/browser.md:229`、`:221`、`:109`

### webview reload 会杀掉所有终端；Win10 1809 之前没有终端
- **现象**：刷新/重载 webview 后所有 shell 消失；或 Win7/早期 Win10 上开终端直接报错。
- **根因**：设计上"一个 tab 一个 shell，不重连"——重载走 `close_all_tabs`；无 ConPTY（build < 17763）时 `portable-pty` 会 panic 并 abort 应用，故 `terminal_open` 主动拒绝。
- **规避**：不要把重载当成"恢复"路径；新增终端功能时守住 `terminal_open` 的 ConPTY 前置检查。
- **证据**：`docs/architecture/terminal.md:212`、`:68`

### `dragDropEnabled: false` 是拖图能用的前提，翻转前要先搬走图片拖放
- **现象**：关掉它之后，把文件拖到非输入区会让 webview 导航走；打开它之后合成器收不到任何拖放。
- **根因**：Tauri 原生文件拖放在页面之前吃掉所有 drop（Windows 上连 HTML5 drag 事件都吞掉）；而 `tauri://drag-drop` 无人监听。
- **规避**：保持 `false`，并依赖 `OMP_IMAGES.refusesStrayDrop` 拒掉越界 drop；需要路径的功能不能单独翻回去。
- **证据**：`src-tauri/tauri.conf.json:31`；`src/app/image-attach.js:77`；`src/app-live.jsx:160`；`AGENTS.md:206`

## 安全边界

### Markdown 渲染进的是持有 `window.__TAURI__` 的 origin
- **现象**：一条含 `<img onerror>` 的助手消息在 dev 下能跑任意 JS——即等价于直接调 IPC。
- **根因**：`dangerouslySetInnerHTML` 与 `window.__TAURI__` 同源；dev CSP 仍是 `'unsafe-inline'`，渲染器是**唯一**守卫。
- **规避**：见前文"Markdown 里的原始 HTML 必须整体转义"；不要加标签白名单替代渲染器。
- **证据**：`src/design/ui/markdown.jsx:36`、`src/design/ui/plan-annotations.jsx:77`；`AGENTS.md:200`

### 任意 `<a href>` 会把应用 webview 顶层导航走，且无法返回
- **现象**：点一下聊天里/ diff 里的链接，整个应用变成那个网页，返回不了，只能退出并丢掉所有 tab 的会话状态。
- **根因**：marked 渲染的链接没有 `target`，webview 自己完成了顶层导航，无人拦截。
- **规避**：`navigation_guard.rs` 的 `on_navigation` 只允许自有 origin 的 `/` 或 `/index.html`（且无 query），其余 `http(s)`/`mailto` 交给系统 opener。
- **证据**：commit `5c8aa37`（#14）；`src-tauri/src/navigation_guard.rs:56-63`；`src-tauri/src/lib.rs:1451`

### Widget 插件在"审批后、运行前"可被换掉（TOCTOU）
- **现象**：安全审计场景——审批时看到的是脚本 A，实际跑的是被替换的脚本 B。
- **根因**：先校验路径、再按路径 spawn，中间存在时间窗。
- **规避**：每次 spawn 前都对 `ApprovalStore` 做指纹校验，并运行该次校验所哈希的**副本**（`store/<fingerprint>/`），绝不运行被校验的脚本路径；代价是 `$(dirname "$0")/…`、相对 `import`、`npx.cmd` 之类找不到同目录文件。
- **证据**：commit `7056b8e`；`src-tauri/src/widgets/snapshot.rs:1-22`；`docs/architecture/widgets.md:216`；`CHANGELOG.md:64`

### 审批授予要绑定到"那一个 prompt + 那一个进程"
- **现象**：在 A tab 点"Approve and remember"，实际批准了另一个 tab（或重启后的同 id 进程）里同工具的请求。
- **根因**：前端只报 session id 与 request id 时，无法区分跨 tab、跨 respawn、已回答、已授予的 prompt，规则可能落到别的会话或项目作用域。
- **规避**：`approval_approve_and_grant` 只接受前端给出的 session/request id，工具与项目由 Rust 从该 session 活进程转发的未回答 prompt 里查出；claim → 写答案 → 授权三步顺序不可颠倒（先授权会让同一进程的其它 prompt 被自动放行）。
- **证据**：`src-tauri/src/agent/approvals.rs:1-12`、`:126-145`；commit `f2a1263`、`4e34f43`

### 终端 shell 以用户全权运行，且不受审批模式约束
- **现象**：把模式调成 `default` 后，仍可在终端里为所欲为；或误以为审批规则覆盖终端。
- **根因**：设计如此——终端是"用户的终端，不是 agent 的"；agent 既不能读也不能驱动它，其输出也不进 prompt。
- **规避**：不要在该路径上补"审批"，也不要让 agent 有机会写入终端。
- **证据**：`docs/architecture/terminal.md:204`；`docs/architecture/approval-mode.md:81`

### 远程访问：push 端点白名单与设置必须全量提交
- **现象**：配对手机能让桌面往任意主机发请求；或改一个设置项把其它项清零。
- **根因**：手机端提交的订阅/设置若被信任，就是 SSRF 与配置破坏面。
- **规避**：订阅只接受 `https` 且域名在 `fcm.googleapis.com` / `updates.push.services.mozilla.com` / `*.push.apple.com` / `*.notify.windows.com`；`remote_apply_settings` 收**完整** settings 对象，永远不要发部分对象。tracker 的 `on_frame` 必须 O(1) 非阻塞。
- **证据**：`docs/architecture/remote-access.md:94`、`:97`；`AGENTS.md:211`

### macOS 缺本地网络用途描述，工具连不上局域网
- **现象**：即使已在"隐私与安全性 → 本地网络"里打开应用，`kubectl`、MCP server、widget 插件的连接仍被内核静默丢弃（`reason: NECP`）。
- **根因**：macOS 把应用启动的**所有**子进程连接都归因到父应用，没有 `NSLocalNetworkUsageDescription` 就不会弹授权。
- **规避**：`Info.plist` 里必须保留该键；删掉它等于让所有局域网工具静默失败。
- **证据**：`src-tauri/packaging/Info.plist:17-19`、`:40-41`；commit `79d1a41`；`CHANGELOG.md:31`

### 浏览器标注层只能用 CSSOM 与 `textContent` 绘制
- **现象**：在开启严格 CSP / Trusted Types 的站点上标注层完全不出现（或抛 Trusted Types 违规）。
- **根因**：页面 CSP 会拦截 `innerHTML` 与内联样式字符串。
- **规避**：`overlay.js` 只用 `element.style.*` 与 `textContent`；在 `omp-annotate` 隔离世界里**按每个 attached page target** 安装（含当前文档与后续导航），且一次 pick 只在面板自己发出的鼠标释放之后 2 秒内有效。
- **证据**：`src-tauri/src/browser/annotate/overlay.js:6`；`src-tauri/src/browser/annotate/pick.rs:130`；`docs/architecture/browser.md:150`、`:163`；`AGENTS.md:190`

|---|---|---|
| 所有 tab 空白、无报错，重启后恢复 | omp 不在子进程 PATH 里（MSI 重启只给机器 PATH / macOS GUI 最小 PATH） | `src-tauri/src/child_path.rs`、`agent/spawn.rs` 的 `Omp::locate`；stderr 里是否有版本或 exec 错误 |
