# 前端状态管理全景

项目**没有** Redux/Zustand。状态分五层，各有明确归属：

| 层 | 位置 | 归属 | 生命周期 |
|---|---|---|---|
| L1 后端状态 | Rust 各 manager / store | Rust | 进程级 |
| L2 桥状态 | `live.js` 的 `state` + `sessionSnapshots` + `sessionRegistry` | 活动标签页 / 每标签页 | 标签页级 |
| L3 纯 UI 偏好 | `localStorage: omp-desktop:tweaks` | 全局 | 跨启动 |
| L4 桌面自造 UI 状态 | React（`app-live.jsx` 与钩子） | 每标签页或全局 | 组件生命周期 |
| L5 组件局部状态 | 各组件 `useState` | 组件 | 挂载期 |

## L2：`live.js` 的 state（每标签页）

`state` 是**当前活动标签页**的活变量；切走时整体快照进 `sessionSnapshots`，切回时整体恢复。

| 字段 | 含义 | 来源 | 何时清 |
|---|---|---|---|
| `messages` | 转录 | `message_start/update/end`、`get_messages` 合并 | `_resetSessionVars` |
| `isStreaming` | 是否正在流式 | 帧 | 同上 |
| `model` / `thinkingLevel` / `ctx` | 模型、思考级别、上下文用量 | `get_state`、`thinking_level_changed`、`set_model` 响应 | 同上 |
| `kanban` / `planMeta` | 计划看板 | todo 工具帧 | 同上 |
| `models` / `commands` | 可选模型、命令列表 | `get_available_*` | 同上 |
| `activity` / `sparkline` | 60 秒活动日志 | 工具帧 | 同上 |
| `exitReason` | 进程退出原因 | `agent://exit` | 新进程 |
| `asyncPending` | omp 报告的背景工作 | `get_state.hasPendingAsyncWork` | `session_settled` / 进程死 |
| `trimmed` | 转录头部是否被裁 | `_trimMessages` | 新进程 |
| `subagents` | 子 agent 摘要 | `subagent_*` 帧 | `_resetSessionVars` |
| `subagentTranscripts` | 子 agent 转录尾部 | `get_subagent_messages` | 切标签即丢（不参与快照） |
| `queue` | omp 的 steer/follow-up 队列 | `queue_update` / `get_state.queuedMessages` | 进程退出 |
| `queueSending` | 已发未确认的"发送中"行 | 本地追加 + omp 回执 | 进程退出 |
| `goal` | goal 模式状态 | `goal_updated` / `get_state.goal` | 进程死 |
| `extWidgets` | omp 扩展状态行与 widget | `extension_ui_request`（`setStatus`/`setWidget`） | `/new`、branch、fork **保留**；进程死清除 |

**`sessionRegistry`**（`Map<sessionId, entry>`）是标签页注册表，跨标签页存活：

```js
entry = {
  path, profile, name,               // 创建时
  sessionFile,                       // resume 用，由 get_state 刷新
  approvalMode,                      // start_session 解析结果
  processStartedAt,                  // 会话树据此判定"冷缓存"
  autoRenameArmed/InFlight/Turns/Left/SessionId,  // 自动重命名状态机
  lastTurnOk,
  label, color,
}
```

## L3：tweaks（`localStorage`）

`TWEAK_DEFAULTS`（`src/app/constants.js:28`）是唯一默认值表，共 35 个键：

| 分组 | 键 |
|---|---|
| 外观 | `theme`、`density`、`accent`、`monoChat`、`fontSize` |
| 布局 | `layout`、`sidebar`、`sidebarWidth`、`splitWidth`、`railWidth`、`treeWidth`、`browserWidth`、`defaultSide` |
| 聊天 | `foldThinking`、`foldTools`、`collapseAfter`、`followOutput`、`promptHistoryLimit` |
| 面板 | `showContext`、`showRadar`、`showSubagents`、`showMinimap`、`terminalAutoOpen`、`terminalHeight`、`terminalScrollback`、`browserLocalhostInPanel` |
| 行为 | `submitKey`、`pasteCollapseLines`、`restoreTabs`、`confirmBusyClose`、`autoName`、`autoCompaction`、`autoRetry` |
| 更新 | `updateCheck`、`skippedUpdate` |

另有前缀键：`widget:plugin:<id>`（轨道插件开关）、`widget:ext:<key>`（扩展 widget 开关）。

**读取方式有两种**：

- React 内：`useTweaks(defaults)` → `[values, setTweak]`，写入即落 `localStorage` 并派发 `tweakchange` 事件。
- React 之外（`live.js` 启动时就要读）：`window.OMP_TWEAKS_STORE.read()`。这是 `restoreTabs`、`autoName`、`autoCompaction`、`autoRetry` 能在任何组件挂载前生效的原因。

**注意**：`foldThinking` / `foldTools` 默认 `null`（未选择），由 `OMP_COLLAPSE.foldModes` 解释为 `auto`；旧键 `autoCollapse` 仍被识别为"open"。

## L4：桌面自造状态（React）

| 状态 | 位置 | 键 | 为什么不进 `live.js` |
|---|---|---|---|
| `drafts` | `design/composer.jsx` | 标签页 id | 含附件、折叠粘贴、历史召回位置、在飞图片计数——omp 从不感知 |
| `plans`（plan 模式） | `app-live.jsx` | 标签页 id | 同上 |
| goal 编辑态 | `use-goal-mode.jsx` | 标签页 id | 同上 |
| 折叠开关 `overrides` | `app-live.jsx` | 标签页 → `_id` | 纯视图 |
| 侧列选择（rail/tree/browser） | `app-live.jsx` | 标签页 id | 纯视图（`OMP_SESSION_UI.seedEntries` 只播种一次） |
| `stab`（设置标签页） | `app-live.jsx` | 全局 | 非会话，不持久化 |
| 每个标签页的面板状态 | `useTerminal` / `useBrowser` / `useWidgets` / `useGitBrowser` 等钩子 | 标签页 id | 由 Rust 事件驱动 |

草稿与折叠开关都经 `OMP_SESSION_UI.entryOf/updateEntry/pruneEntries`（`app/session-ui.js`，回归 `test-session-ui.mjs`）存取，标签页关闭时剪除。

## L5：组件局部

`Composer` 刻意**不随标签页重挂载**：重挂会让 `draftInsert`/`promptInsert` 副作用重跑，正在准备的图片可能落进错误的标签页。

## 数据流向图

```
Rust ──event──▶ live.js ──notify()──▶ OMP_BRIDGE.onUpdate ──▶ useBridgeSnapshot ──▶ React setState
                   ▲                                                            │
                   └──────────── OMP_BRIDGE.xxx() ◀── 组件回调 ◀─────────────────┘

localStorage ◀──▶ useTweaks ──▶ settings-schema 渲染 ──▶ React
```

**`notify()` 是唯一的推送点**：它同时负责布局持久化（`_persistLayout`）。任何新状态若不经过 `notify()`，UI 不会更新。
