# 组件架构与通信

`src/app-live.jsx` 是**唯一** React 根（1124 行），所有其它组件都是函数组件，没有路由、没有 Context Provider 树、没有 CSS-in-JS。

## Props 流向（三条规则）

1. **只向下传值**，回调向上。没有全局事件总线；跨组件通信一律经过 `App` 的 state 提升。
2. **桥数据经 `useBridgeSnapshot(bridge, setters)`**（`app/use-bridge-snapshot.jsx`）把 23 个字段灌进 `setState`。这是唯一订阅 `OMP_BRIDGE.onUpdate` 的地方。
3. **`window.*` 全局用于跨"加载单元"引用**：纯逻辑模块（`OMP_*`）、UI primitives（`Icon`、`usePopoverDismiss`、`useDragReorder`）、以及后面定义的组件（`composer.jsx` 渲染 `<QueueStrip>` 是按名字查找，不顶层解构）。

## 为什么用全局而不用 import

没有打包器。每个 `<script>` 是独立的执行单元，模块间唯一的共享面是 `window`。由此产生三条硬规则：

| 规则 | 后果 |
|---|---|
| 普通脚本必须 IIFE 包裹并挂 `window.X` | 否则顶层 `const` 会在共享作用域里重名 → `Identifier already declared` |
| Babel 脚本共享顶层作用域，解构必须用唯一别名 | `_TD_Fmt`、`_CT_Row`、`_GB_`、`_PSet_` 等前缀存在的原因 |
| 顶层解构必须在其定义脚本之后；函数体内查找是晚绑定 | 顺序错 → 静默 `undefined` |

## 事件与副作用分布

| 关注点 | 归属 | 说明 |
|---|---|---|
| 键盘 | `app/use-keymap.jsx` + `app/keymap.js` | 动作注册表 + `guestShouldBypass`（终端/浏览器页面把哪些键交还） |
| 主题与字体 | `useThemeEffect`（`use-bridge-snapshot.jsx`） | 写 `<html>` class 与 CSS 变量 |
| 终端 | `useTerminal` | per-tab xterm、事件监听、replay 执行 |
| 浏览器 | `useBrowser` | 面板 channel、标注 chip、canvas 输入 |
| 远程 | `useRemote` | 发布活动标签页视图、串行动作执行 |
| widget | `useWidgets` | `widgets://` 事件 + 视图状态上报 |
| 会话树 | `useConversationTree` | 打开即重取 |
| git 浏览器 | `useGitBrowser` | 惰性取数 |
| 列宽 | `usePaneWidths` + `ui/use-edge-drag.js` | CSS 变量 |
| 更新 | `useUpdater` | 启动 15 s 后检查，之后每 6 h |

## 模态与浮层

| 类型 | 实现 | 焦点处理 |
|---|---|---|
| 全窗口覆盖（git 浏览器） | `.gitb-scrim` / `.gitb` | — |
| portal 模态（预览、图片灯箱） | 渲染进 `<body>` | `useModalLayer` 把 `#root` 设为 `inert`，关闭时归还焦点 |
| 下拉菜单（profile、thinking、PathPicker） | 组件内 | `usePopoverDismiss`（外点/Esc）+ `menuKeyNav`（方向键/Home/End/Tab） |
| 设置页搜索 | `SettingsPage` 内 | 页面级 capture 监听 Esc（`data-st-esc` 例外） |

## 渲染性能约定

- `chat-view.jsx` 的 `React.memo` 包住气泡；因此传给它们的 props 必须是**布尔 + 稳定回调**（`chat-collapse.js` 的折叠判定正因此把每个 block 的 props 限制为两个）。
- 折叠剪裁保持内容在 DOM 中（不被 `inert`），否则预览文字无法选中。
- 隐藏的终端/设置面板用 `hidden` 而非卸载，保住 xterm 实例与设置页的滚动位置。
- widget 卡片有 `WidgetBoundary`（每个卡片一个错误边界），一个插件崩了不影响其它卡片。
